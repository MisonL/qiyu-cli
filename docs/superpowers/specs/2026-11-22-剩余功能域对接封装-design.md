## 2. P0 · Windows 凭证权限：证据链与裁决

### 2.1 三层失效（【已验证】，静态 + 真机）
- **写入不收紧**：`writeConfigFile`（`src/core/config.ts` 的 `writeConfigFile`）在 win32 上 `mkdir mode:0o700`「Not supported on Windows」、`writeFileSync{mode:0o600}` + `chmodSync(0o600)` 只映射「只读属性」——**NTFS DACL 零改变**。
- **门禁不拦截**：`checkPermissions:371` 首行 `if (process.platform === 'win32') return {ok:true}`，「含凭证过宽即拒绝」在 Windows 上整条蒸发（连警告都没有）。
- **自检恒 ok**：`auth login` 写后自检调 `checkPermissions`（`auth.ts` 的「权限自检」段），win32 短路使它在 Windows 上 **恒返回 ok**——`configured:true` 里的「权限已复核」这层含义在 Windows 上没有发生；而同一函数上方的注释把 「凭证已落盘且可被他人读却报成功」定义为假成功，win32 路径恰好落进自己定义的形态。 · **边界澄清（Codex P1-4）**：自检的 `catch { }` 吞错是**另一件事**——它对全平台一致、注释写明是有意的 （「自检失败不影响已写入这一事实；下一次任何命令都会再查一次」），不是 win32 特有。 spec 此前把两者压成 「自检恒真」一句，读起来像 catch 也是 win32 分支——修法里两者要分开对待。- **影响面（按调用链列，Codex P1-4 要求）**：`writeConfigFile` 的直接写入方只有 `auth login`；`checkPermissions` 直接调用点三处 （login 自检、`loadConfigChecked`、`store/config.ts resolveStoreConfig`），传递覆盖 `auth whoami`、`api call`、 `sync run/status/verify/install/uninstall`、`store/db/query/stats` 全族与限流 fallback 探测；`api list`/`api schema`/ `skill *`/`--version` 不读配置，不在其内。

### 2.2 真机决定性证据（M1 + 我亲自复核 T-8/T-7a）
- **M1（有效证据）**：Windows 上 0600/0644/0666 四种造法的文件，`icacls` 输出**逐字节相同**、`statSync().mode` 全部回读 `666`；把 config.json 显式 `/grant` 给 `Everyone:(R)` + `BUILTIN\Users:(R)`（**RC=0、ACE 在、含凭证**）后 `auth whoami` **RC=0** 照常返回 `configured:true`，不报 `config_insecure`；`icacls /reset` 回纯继承后仍 RC=0。
- **T-8**：git 历史证明两个函数自 `5650cfa`(G1/v0.2.0) 引入、v0.2.1→v0.2.3 函数体哈希相同 ——「非 0.2.2 回归」 **这一半是源码历史可复核的**；另 一 半 「三版产物在 Windows 上 ACL 逐字节相同」只是**本机样本观察** （原始输出见 `private/evidence/2026-11-22-windows-acl/raw-outputs.md`，gitignored），不推广为普遍结论。该缺陷是 **G1（PR #13，v0.2.0 起）的存量**，0.2.2 在权限域反而往诚实方向走（新增 ACL 拒绝的平台分流）。用户「0.2.2 起」是观测时点，不是回归点。
- **T-7a（精确归因）**：M1 环境中那条**测试机特有的某沙箱服务组**的 `(I)(M,DC)` ACE 来自 `%TEMP%` 目录本身（新建任意文件都继承），**不是 qiyu 写入的、也不是全体登录用户可读**。真实暴露面按「NTFS 默认 ACL 可能授予广域主体 + CLI 不检查也不告警」陈述，**不夸大**成「所有登录用户可读」。
- **T-8 附加**：Windows上 `os.homedir()` 只认 `USERPROFILE`（HOME 完全忽略）；OpenSSH 会话里 `USERPROFILE` 指向 Temp——路径契约在 Windows 上比预想复杂。
- **我方探针诚实记录**：我自己跑的一轮「放宽 Everyone 后 whoami rc=0」是**无效探针**（凭证从 env 读、`grant` 静默失败、ACE 没落上）；「门禁不拦」只以 M1 那份有效证据为准。

### 2.3 Linux 正确基线（M2，全实测）
文件 600 / 目录 700 且与 umask 077/022/**000** 无关；644 → whoami rc=1 `config_insecure` + `chmod 600` hint；目录 757/777 → 拦、755 不拦（判据 `&0o022`）；把 login 产物复制成 644 后 `nobody` 真能读出 secret（泄露面真实）；644 下 `login` 静默自愈为 600、777 目录下 login 报「已写入但自检不合格」；符号链接**只写侧拒绝、读侧跟随**。

1. **方案 B（立即，低成本诚实）**：README(:122、:176-193)、design(:169/:185)、`errors.md` ①档、`auth login` help/field_notes、`writeConfigFile` 注释统一收窄为「POSIX 域承诺；Windows 上 mode 不落 ACL、CLI 不检查也不告警，暴露面由 NTFS 默认 ACL 决定，需人工 `icacls`」；把无条件 `statSync().mode & 0o777` 断言逐处平台化（清点：`tests/core/config.test.ts:283,284,295,302` + `tests/commands/auth.test.ts:237,238` 共 6 处，另有两文件各自的 `writeCfg(mode=0o600)` 夹具默认值）。
2. **方案 A（以真机为闸，机制结论见 §2.4a）**：写入侧 win32 显式 `icacls /inheritance:r /grant:r "*<当前用户 SID>:(R,W)"`——数值 SID **必须带 `*` 前缀**（`icacls` 语法要求，实测同此），且按 **SID** 不按本地化 trustee 名（中文 Windows 的 `icacls` 输出是本地化的——同「按错误文本分流」红线）；**写序与 ACL 落点（CodeRabbit #82 major 的追问）**：`writeConfigFile` 是「写 tmp → `renameSync` 换入」。 `rename` 是**换入对象**——换入后目标的 ACL 取 **源文件（tmp）**的，**目标旧 DACL 不保留**（**实测 T-9b**：对已显式放宽过 `Everyone:(R)` 的目标做 `mv` 覆盖，换入后 ACL 变成 tmp 的目录继承态、旧 `Everyone` 授权消失）。所以"保留旧 DACL 再写凭证"这条泄露路径在 **当前 tmp→rename 形态下不成立**。**写序必须拆成各自可验证的步骤（Codex 对 PR #82 的 P1-1——比 rename 语义更早的一处泄露；round 77/79 后又补了 ⓪ 与创建时刻受限，现在共五步）**：win32 上 `writeFileSync(tmp, secret)` 会按父目录继承的 DACL 创建 tmp，**secret 在被收紧之前就已经躺在 tmp 里**（当前代码先写后 `chmod`，而 `chmod` 不落 DACL → 整个写入窗口 tmp 都是继承可读的）。正确顺序：⓪ **建 tmp 之前先校验父目录受信**（清单第 7 条；不可信就直接失败，**不建 tmp、不写 secret**——CodeRabbit round 77：tmp 会继承父目录 ACL，事后收紧救不回来）；① **以受限安全描述符原子地创建空 tmp**（不写 secret；**2026-11-24 两轮真机探针后此步的落地形态见 §2.4a「设计据此收敛」——主路线改为「创建后立刻自检 tmp 的 DACL」**）——CodeRabbit round 79：父目录对他人有**可继承的只读** ACE（第 7 条只拦写面、放行这种）时，tmp 创建瞬间就继承可读，别人可在收紧前打开并**持有句柄**，而 Windows 只在**打开时**检查访问、改 DACL 不撤销已授予的访问；所以「`writeFileSync` 之后补 `icacls`」不满足要求，必须创建时刻就受限。候选机制：① Win32 `CreateFile` + `SECURITY_ATTRIBUTES`（需原生/P-Invoke 封装）；② 在**创建时刻即受限**的 staging 目录内建 tmp（该目录本身同样要用本机制创建，不得「先建目录再 `icacls`」，否则问题递归）；③ 若当前技术栈两者都做不到，**如实声明残余风险**（窗口多长、需要什么权限才能利用），不写「已保护」。三种机制**均未真机实测**，0.2.4 实施前必须验；② 对它 `icacls /inheritance:r /grant:r "*<SID>:(R,W)"` 收紧，并**读回确认收紧成功**；③ 收紧到位后才写 secret，**且必须写进 ① 创建时拿到的同一个句柄**（不得按路径重新打开——round 81：`qiyu` 目录的**祖先**若对他人可替换子项，对方可在 ② 之后把 `qiyu` 目录换掉、在同一路径放另一个 tmp，按路径重开会把 secret 写进攻击者可读的文件；**目录身份必须先钉住**：打开 `qiyu` 目录的句柄并保持到 ④ 完成（Windows 上持有目录句柄可阻止其被删除/改名——**前提是打开时不得带 `FILE_SHARE_DELETE`**：共享标志里给了删除共享，别人照样能删/改名，句柄形同虚设；Codex round 24），或在 ② 与 ③ 两边比对同一路径下对象的 **file ID / 卷序列号**，不一致即中止）；④ `renameSync` 换入（换入前对目标路径再比对一次目录身份）。**任一步失败就删除 tmp 且不换入**（不留一个收紧失败、含 secret 的文件在继承目录里）。换入后目标的 ACL 继承自这个已收紧的 tmp——「换入会把收紧带过去」只有在「先收紧再写入」的前提下才成立，否则只是把带 secret 的宽松 tmp 换进目标位置。**若**将来改成对现有文件 **原地改写**（不走换入），则 `/inheritance:r` 只断继承、`/grant:r <自己>` 不删**他人已显式授予**的 ACE——旧的 `Everyone`会存活，那种形态必须额外 `/remove` 广域主体。**收尾一律对最终路径复核一次 ACL **（见下探测），别假设写序正确。`checkPermissions` win32 分支改**真探测 ACL**——探测不能只看「当前用户可不可达」，必须**枚举现有 ACE 并按「最小允许名单」判**：只有当前用户 SID（以及 `*S-1-5-18` SYSTEM、`*S-1-5-32-544` BUILTIN\Administrators 这两个设计上本就等价全权的内置主体）可以持有允许 ACE，**出现任何其他主体的允许 ACE 即判 `ok:false`，不论它是不是广域主体**。**不得写成广域主体黑名单**（Everyone/Users/Authenticated Users 枚举）——黑名单天然漏一族：`icacls /grant:r <某个具名用户>:(R)` 的显式授权不在名单里，却同样让那个账户读到 `appSecret`，探测却报 `checked:true, ok:true`（CodeRabbit round 74 指出的正是这一形态，与本 spec「凭证可被他人读却报成功」的定义同类）；那个具名用户即使在别处有 deny ACE 也按「先判 allow 名单」处理——宁可误报要求人工 `icacls` 清理，也不放过。**「空名单」不等于「已保护」——必须先把 DACL 本身的存在性与空态判掉（CodeRabbit round 75）**：Windows 的 **null DACL**（安全描述符里 `DACL` 指针为空）表示「无访问控制」——**所有人都拿到完全访问**，它枚举出来的 ACE 列表同样是空的，光按「没有名单外主体的允许 ACE」判会把这种最危险的形态判成 `checked:true, ok:true`。**探测的对象不是「ACE 列表里有没有已知坏形态」，而是整份安全描述符是否处于「受信状态」**——逐轮补黑名单式缺口（round 74 具名用户、round 75 null DACL、round 76 属主）说明这个方向本身会一直漏，所以判据改成封闭清单，**任一条不满足即 `ok:false`**：
1. **DACL 存在**（null DACL = 「无访问控制」，所有人完全访问 → 拒）；
2. **DACL 非空**（空 DACL = 「显式拒绝所有人」，文件连当前用户都读不了，不是本 CLI 写序可能产出的形态 → 拒并提示重建 ACL，不得当成「收紧得好」放行）；
3. **属主（owner SID）∈ {当前用户 SID, `*S-1-5-18` SYSTEM, `*S-1-5-32-544` Administrators}**——非受信账户作属主时，属主隐含 `WRITE_DAC`，可以随时给自己补一条读 ACE，ACE 名单里永远看不出来（CodeRabbit round 76）；
4. **所有允许 ACE 的主体 ∈ 同一受信集合**（出现任何其他主体即拒，不论广域与否——round 74）；
5. **当前用户的允许 ACE 至少含读权限**（否则 CLI 自己读不了配置，「收紧成功」是假的）；
6. **继承关闭**（`SE_DACL_PROTECTED` 置位）——继承开着时，父目录 ACL 一变就会把名单外主体重新带进来，当前这份 ACE 列表「碰巧干净」不构成保证；
7. **父目录的写面受信**（不是「所有 ACE 都受信」）：非受信账户对目录没有任何**写类**权限（创建/删除子项、`WRITE_DAC`、改属主）——否则别人可以**整个换掉**这个文件；继承来的**只读** ACE 只暴露文件名、读不到 `appSecret`，与 POSIX 侧「目录 0755 不拦、group/other 有写位才拦」（`checkPermissions` 目录分支的 `& 0o022`）同构；
8. **任一条判不了**（非 NTFS、PowerShell/icacls 不可用、SDDL 解析失败）→ `checked:false`，不冒认 ok。
候选机制是 PowerShell `Get-Acl` 的 SDDL 形态（null DACL 为 `D:NO_ACCESS_CONTROL`、空 DACL 为 `D:`，两者枚举 ACE 都是空列表，**只有 SDDL 能区分**）——该机制**尚未真机实测**，实施前必须在 Windows 真机上各造一个（`icacls` 能造空 DACL；null DACL 需 PowerShell/.NET 设置 `SetSecurityDescriptorSddlForm('D:NO_ACCESS_CONTROL')`）并读回确认，实测定稿前不把这条写成「已验」。判据取 **SID + 访问掩码**，不解析 `icacls` 输出里的本地化权限文本（`(F)/(M)/(RX)/(R)` 一类 token 的中文输出形态**未经实测**，不拿它做判据；取 SID/掩码的候选机制——PowerShell `Get-Acl` 的 `FileSystemRights` 枚举值 + `Translate([SecurityIdentifier])`——需真机验证后再定稿）；按 **SID** 判不按本地化名，规避中文 Windows `icacls` 输出本地化——同「按文本分流」红线；收紧用的是**重建整份 DACL**（断继承 + 删他人显式 ACE + 仅授当前用户），`/grant:r <自己>` 单用**不会删别人的显式授权**，残留即泄露；返回三态 `{ok:true, checked:true|false}`，三个调用点（`auth login` 的「权限自检」段、`core/config.ts` 的 `loadConfigChecked`、`store/config.ts` 的 `resolveStoreConfig`）把「判定不了」如实透出；不得复用 `mode & 0o077` 判据（Windows 正常文件回读 666，会把所有人误拒）。非 NTFS / icacls 不可用 → 「判定不了」，不冒认 ok。
3. **同构面裁决**：`store init` 创建的 DuckDB 库文件（含业务数据）同样无权限收紧——要明确「一并收口」还是「明确非目标并声明」，不留下沉默缺口。

### 2.4a 机制真机探针结果（2026-11-24，三轮；原始输出见 gitignored 存档）

在 Windows 10 19045 / PowerShell 5.1 上对 §2.4 的候选机制做只读探针（临时目录，测完自删）。
三轮的起因都是审查：第一轮列机制、第二轮（CR 86）推翻第一轮的「只能引原生依赖」、
第三轮（CR 89）验证独占句柄语义。


**已验证可行**
- `Get-Acl` 的 `.Sddl` 可读，ACE 可逐条取类型 / 是否继承 / 主体 SID（`Translate`）/ 权限 ——
  「不解析 `icacls` 本地化文本」这条判据路线成立。
- **原子地以受限 SD 创建文件可行，且不需要额外程序集**：`System.IO.FileStream(path, FileMode, FileSystemRights,
  FileShare, bufferSize, FileOptions, FileSecurity)` 这个构造重载在 **PowerShell 5.1 / .NET Framework** 上
  可用，实测产出的 SDDL 是 `D:P(A;;…;;;<当前用户 SID>)`——受保护 DACL、仅当前用户。
  （第一轮只试了 `System.IO.FileSystem.AccessControl` 的扩展方法，它在 5.1 加载不了，据此下的
  「只能引原生依赖」结论**错误并已撤回**。）
- 该机 `%TEMP%` 下的新文件继承了一条**非受信主体的 Modify ACE**（沙箱服务组）——「父目录对他人有
  可继承权限」有真实可造形态。
- **独占打开本身就是探测（第三轮）**：他人持有读句柄时 `FileShare.None` 打开**当场失败**；我方独占持有
  期间他人打不开、`icacls` 照常可用、`rename` 被拒（须先关句柄）。这把「攻击者已拿到句柄」从推断
  变成可观测（② 的实现依据）。

**已验证不可行 / 需谨慎表述**
- **`[System.IO.File]::Open` 打不开目录**（访问被拒绝）→ 「持有目录句柄（不带 `FILE_SHARE_DELETE`）
  阻止改名」需要 P/Invoke `CreateFile` + `FILE_FLAG_BACKUP_SEMANTICS`，纯 .NET/Node 面不可用。
- **null DACL 的判据只能从 SDDL 形态间接确认**：设 `D:NO_ACCESS_CONTROL` 后 `Get-Acl` 的 SDDL 里
  `D:` 段消失、`icacls` 报「该文件没有 DACL」一类本地化报文，但 .NET 的 `.Access` 仍返回 1 条——
  **没有做原生描述符读回**，不得声称「已用原生 API 验证是 null DACL」。
  ⚠️ **null DACL 与「显式 Everyone ACE」不是同一条判据**（CodeRabbit round 87）：显式 Everyone ACE
  会出现在 ACE 列表里，只走允许名单的实现能拒掉它；**缺失 DACL 时 ACE 列表是空的**，只走允许名单
  的实现会把它判成「干净」。所以夹具 6 只有在实现**先判 DACL 存在（清单第 1 条）**时才算覆盖，
  「两种形态都判 `ok:false`」只对**完整清单**成立，不是允许名单单条判据的等价性。
- **空 DACL `D:` 的设置静默不生效**（SDDL 读回与设置前一致）→ 夹具 7 在本机**造不出来**，
  实施时必须如实标注。

**设计据此收敛（实施以此为准，取代 §2.4 里对应的未实测表述）**

主路线：**先建空 tmp，再以独占方式打开它，然后判 DACL、收紧、写 secret——secret 全程只经过这个
独占句柄**。写序：

- ⓪ 校验父目录受信（不满足就失败，并点名路径）。
- ① 以 `CreateNew` 建**空** tmp（不写 secret）。
- ② **以 `FileShare.None`（独占）打开这个 tmp**。这一步本身就是一次真实探测（2026-11-24 真机实测）：
  已有别的进程持有读句柄时，独占打开**会失败**（A）；成功则此后任何其他进程都打不开它（B/C）。
  失败即判定「有人已经摸到这个文件」→ 删除 tmp 并失败，此时文件为空、无 secret 可泄露。
- ③ 读 DACL（同一个路径，此时无人能打开它）：出现任何非受信主体的允许 ACE → 删除 tmp 并失败。
- ④ `icacls /inheritance:r /grant:r "*<SID>:(R,W)"` 收紧并读回确认（真机实测：**独占句柄持有期间
  `icacls` 照常可用**，E）。
- ⑤ **通过 ② 拿到的句柄写 secret**——不许按路径重开（CodeRabbit round 89：按路径重开时，攻击者可在
  收紧后把目录换掉再换回来，四条 `ino`/`dev` 比对全部通过而 secret 落进另一份文件）。
- ⑥ 关闭句柄（真机实测：`FileShare.None` 持有期间 `renameSync` 会被拒绝，D），再比对一次
  `ino`/`dev`，然后 `renameSync` 换入；不一致即删除 tmp 并失败。

**为什么这条能同时关掉前面的洞**：② 的独占打开把「攻击者已持有句柄」从「推断」变成「当场可观测」
（打开失败）；③ 保证这个对象没被写过非受信 ACE；⑤ 保证 secret 写进的正是 ②③ 验过的那个对象；
⑥ 的 `ino`/`dev` 比对兜住「目录被换过」这最后一跳。⓪ 仍然必要（父目录不可信时连 tmp 都不该建）。

**已验证的机制边界（同一台真机，2026-11-24）**
- `FileShare.None` 的独占语义、`icacls` 与独占句柄并存、`renameSync` 需要先关句柄——
  这四条**都有真机输出**（见 gitignored 证据）。
- **Node 的 `fs` 在 Windows 上给不出独占打开**：libuv 打开文件时总是带 `FILE_SHARE_READ|WRITE|DELETE`。
  所以 ②–⑤ 需要一个 **PowerShell 子进程**（或 P/Invoke）来做；纯 Node 实现只能退化为路径式检查，
  那种形态必须**如实声明残余风险**，不得声称已保护。
- PowerShell 不可用 / 非 NTFS → `checked:false`，并且**不写凭证**（fail closed，不冒认 ok）。

### 2.5 回归防线
CI 仅 `ubuntu-latest`（`.github/workflows/ci.yml:18-25`），**无测试钉住 win32 短路本身**。建议最小 windows-latest job（跑不依赖 POSIX 的 auth/config/hint 方言子集）+ 静态守卫钉「win32 短路不得无覆盖静默存在」。ACL 夹具清单（0.2.4 实施时必须齐全，每条都要真机跑）：
1. 纯继承（默认新建）→ 判 `ok:false`（继承 ACE 未收紧）；
2. `/grant Everyone:(R)` → `ok:false`；
3. **`/grant *<另一个具名用户 SID>:(R)`、且无对应 deny ACE** → 必须 `ok:false`——这是防止探测判据退化回「广域黑名单」的最小反例（CodeRabbit round 74）；写成黑名单的实现只有这条会红；
4. 按修法收紧后（`/inheritance:r` + 仅授当前用户）→ `ok:true, checked:true`；
5. icacls/PowerShell 不可用或非 NTFS → `checked:false`，不得冒认 ok；
6. **null DACL**（`D:NO_ACCESS_CONTROL`，等于所有人完全访问）→ 必须 `ok:false`——ACE 列表为空，
   只数 ACE 的实现会把它判成「干净」，这是判据最危险的一种假绿（CodeRabbit round 75）；
7. **空 DACL**（`D:`，显式拒绝所有人的访问）→ 同样 `ok:false` 并提示重建 ACL，不得当成「收紧得好」；
   （**2026-11-24 实测：本机用 .NET 造不出空 DACL——设置静默不生效**；该夹具需另找造法，在造出之前不得声称覆盖。）
8. 正常受限 DACL（夹具 4 的那份）→ 仍须 `ok:true, checked:true`，证明①判空态没有把好形态一起拒掉；
9. **另一个普通账户作属主、DACL 里只授当前用户** → 必须 `ok:false`——属主隐含 `WRITE_DAC`，
   能给自己补读权限，ACE 名单看着干净不代表读不到（CodeRabbit round 76）；夹具 8 是对照组；
10. **继承开启、当前 ACE 恰好只含受信主体** → 必须 `ok:false`（父目录一改就带进名单外 ACE）；
11. **文件本身干净、但父目录对另一个普通账户可写** → 必须 `ok:false`——对方可以删掉再重建，文件 ACL 再紧也没用（与 POSIX 目录判据同构）；
12. **父目录不可信时的写序**：另一个账户先以共享读打开（尚不存在的）tmp 是做不到的，但**父目录可写**时对方可以先创建同名 tmp 占位——必须验证 `writeConfigFile` 在建 tmp **之前**就拒绝，失败文案点名父目录（round 77 的时序要求：改 DACL 不撤销已打开句柄，事后收紧救不回来）；
13. **父目录对他人有可继承的只读 ACE（无写权限）** 分两种合规结局，二者**任一**即通过
    （round 89 修正：原写法要求「全程打不开」，与现行「先建后验」路线冲突）：
    (a) **受限创建路线**（`FileStream + FileSecurity`，实测可用）：tmp 从创建起就只有当前用户可读，
        并发探针在 ⓪–② 窗口内**全程 Access Denied**；
    (b) **先建后验路线**（主路线）：tmp 可能继承到他人可读，但实现必须在**写入任何 secret 之前**
        以独占打开失败或 DACL 自检失败的方式**拒绝并删除 tmp**——探针要能观测到「要么全程打不开、
        要么文件被删且退出码非 0」，且 secret 从未落盘。**只接受「文件还在且里面已有 secret」判红**；
14. **`qiyu` 目录的祖先把「替换子项」权限给了另一个账户**（而 `qiyu` 自身写面受信）→ 对方在 ② 与 ③ 之间把 `qiyu` 换成同名目录 + 另一个 tmp：实现必须**拒绝或检测到身份变化**（目录句柄保持 / file ID 比对），且 secret 全程不进入攻击者能打开的对象——按路径重开 tmp 的实现会红（round 81 的 TOCTOU）；
