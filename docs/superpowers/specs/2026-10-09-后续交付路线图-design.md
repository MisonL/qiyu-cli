## 一、本文件的作用

第一个计划（认证与通用 API 通道，11 个任务）已实现并合入 `impl/auth-and-api-channel` 分支，但那只覆盖设计稿的一小部分。本文件把设计稿**未覆盖的剩余部分**拆成可独立规划、独立实施的子项目，并先定死它们之间的**接口缝**与**顺序**——否则各子项目的 spec 会在边界处打架。

本文件**不**包含实现细节；每个子项目另有一份 spec 与一份实施计划。

## 四、子项目拆解

依赖图（文档写明＋推断，推断处已标注）：

```
A 注册表补全 ──→ B 请求构建/校验
   │
   ├──→ D 同步引擎 ←── C 存储层
   │                        └──→ E 查询与沙箱 ──→ F Skill
   └───────────────────────────────┘
G 契约补强：G1（独立小件）可随时；G2（依赖 C/D）跟在其后
```

### A. 注册表补全（生成脚本）

- **目标**：把 `specs.json` 从 11 条补到 **154 条**（150 文档页 ＋ 4 文档外），并给 `EndpointSpec` 补 `params`/`responseShape`/`category`。
- **产出**：生成脚本（联网抓 `llms.txt` → 150 页 `.md` → OpenAPI YAML → 生成）；154 条提交产物；`registry/params/*.json`（另立，见接口缝）。
- **依赖**：无。
- **验收判据**：
  1. 154 条，`loadSpecs` 全过。
  2. 危险集合 = **16 个 id 逐条枚举**（§5.4 的 10 ＋ 知识库 5 ＋ `settings.wxTemplates`），不得凭"§5.4 只列了这些"推断。
  3. `envelope` 未实测填 `null`；`'D'` 与 `'D-nf'` 分开填。
  4. 3 种畸形路径按规则修（去方法/origin、双斜杠折叠、中文散文→`path:null,callable:false`）；`transferHuman` 路径修正。
  5. `RATE_LIMITS` 的 33 个 id 与注册表 id **对齐**（同路径同档位），并更新对应不变量测试。
  6. 抓取测试走固定样本/mock，不联网。
- **已知风险**：§5.4「标题 12 但表格 10」来源不明（不得编造归因）；`robot/transfer/config` 文档称无鉴权但实测校验 checksum。

### B. 请求构建 / body 校验

- **目标**：`api call` 能用 A 的 `params` 校验或提示 body 字段（当前逃生舱完全不校验）。
- **产出**：待定（可能并入 A 或 E——在 B 的 spec 里决定）。
- **依赖**：A。
- **验收判据**：待 A 定下 `params` 形状后在 B 的 spec 里写（含"必填缺失""字段改名"两类已知陷阱：知识库 `robotId` 必填、`editKnowledgeNoSimilars` 用 `question` 非 `name`）。

### C. 存储层（`store/`）

- **目标**：本地数据仓库，供 D 写入、E/F 读取；只读查询脱离七鱼限流。
- **产出**：`src/store/types.ts`（`Store` 抽象）、`duckdb.ts`（原生 API）、`kysely.ts`（外部后端）、`schema.ts`、错误契约；新增错误 kind `store_locked`/`store_not_initialized`。
- **依赖**：无（数据模型来自设计稿 §6；字段语义靠 A）。
- **验收判据**（多后端带来的三处实测风险必须覆盖）：
  1. **并发**：DuckDB 跨进程锁排他（RW 持有时连 RO 都阻塞）→ 单写者 ＋ 读者指数退避；读者超有界重试后返回 `store_locked`（不得无限阻塞）。
  2. **upsert 语义一致**：`INSERT OR REPLACE` 在 DuckDB/SQLite 语义不同 → 统一用 `ON CONFLICT ... DO UPDATE SET` 显式列全非键列。
  3. **类型**：ID 列统一 `VARCHAR`（`BIGINT` 在 better-sqlite3 静默丢精度）；DuckDB 结果只用 `getRowObjectsJson()`。
  4. **一致性测试**（对应 §12）：DuckDB 与 SQLite 的 upsert/查询结果一致。
- **已知风险**：完整 DDL 设计稿未给（只有表/主键/实测字段清单）；`sessions` 统一 schema 未定（需 `session_type` 分支）。

### D. 同步引擎（`sync/`）

- **目标**：§7——增量/全量/断点续传/缺口记录/限流调度。
- **产出**：`src/sync/engine.ts`、任务目录、导出管线；`sync run/--full/--since/--until`、`sync status/tasks/verify`。
- **依赖**：A（用注册表驱动）、C（写入目标）。
- **验收判据**：`sync run` 幂等；中断后自动续跑；失败范围落 `sync_gaps`；`sync_state` 用 `pending/complete` 区分"未同步"与"空数据"，完整范围成功后才推进水位；知识库全量快照 ＋ 本地按 `updateTime` 增量；会话导出 create→poll→download→unzip→parse，相邻窗口重叠去重、跳过尾部非 JSON 行。
- **已知风险**：报表日期语义不统一；限流状态跨进程未持久化（当前 `TokenBucket` 是进程内 Map）。

### E. 查询接口与沙箱（`query/`）

- **目标**：§8——`db tables`、`db describe <table>`、`query --sql`、`query --table …`、`stats fields <report>`。
- **产出**：查询命令 + **三层只读沙箱**。
- **依赖**：C。
- **验收判据**：沙箱三层**缺一不可**（语句白名单 `extractStatements()`＋`prepare().statementType`；每连接 `SET enable_external_access=false` ＋ `SET lock_configuration=true`；`access_mode=READ_ONLY`）。无防护时可穿透的攻击（`COPY TO` 写文件、`read_csv('/etc/passwd')`、`read_text`、`glob`、`ATTACH`、`EXPORT`、`INSTALL httpfs`、SSRF、多语句）**全部被拦**。
- **已知风险**：`access_mode=READ_ONLY` 单独完全不够；`enable_external_access` 不持久化，每次连接都要设。

### F. Skill（§11）

- **目标**：给 Agent 的操作协议 ＋ `skill check` ＋ `skill_contract_version`。
- **产出**：待定——**Skill 的文件格式/目录设计稿未规定，必须在 F 的 spec 里先解决**。
- **依赖**：A、E。
- **验收判据**：不硬编码表名/列名/错误码/完整 SQL（运行时经 CLI 自描述取值）；`qiyu skill check` 能校验其引用的命令/表/字段确实存在；输出 `skill_contract_version`。

### G. 契约补强（分两批）

- **G1（独立小件，可随时）**：`method:'GET'` 不带 body 分支；`RateLimit.scope`（待确认七鱼是否存在全局配额）；`auth login`（配置文件写入）；`--pretty` 人类可读输出。
- **G2（依赖 C/D）**：§9.2 静默失败防护剩余项（`resolved_range`/`data_coverage`/`last_synced_at`/`truncated`、时间过滤 0 行 warning、表/列候选提示）；§9.3 时区（相对时间按 `Asia/Shanghai` 解析并回显 `resolved_range`）；§9.4 名称解析（`--assignee "张三"` → staffId，歧义返回 `kind:"ambiguous"` ＋ `candidates`，以 `username` 为解析键、组名用完整路径）；§12 三条测试策略（厂商 Java 签名样例对拍、40 种信封表驱动、store/sync 测试）。

## 五、接口缝（先定，避免 specs 打架）

1. **`EndpointSpec` 扩展**：`params`/`responseShape` **不进 `specs.json`**，另立 `registry/params/*.json`（否则 `api list` 的产物文件会胖到几百 KB，而 `api list` 只需元数据）。
2. **`Store` 抽象**（C 定，D/E/F 消费）：设计稿只有命令示例，无代码级签名。C 的 spec 必须定死：表清单、`describe(table)`、只读查询入口、锁语义。
3. **分层**：`core/` 不 import `commands/`（已有约束）；`store/` 不 import `sync/`（设计稿 §3）。
4. **错误 kind 扩展**：C 新增 `store_locked`/`store_not_initialized` 时，须同时更新 `ErrorKind`（首个计划已给 `needs_confirmation` 补过同类）。

## 六、顺序与并行

1. **A** 先行（D/E/F 的共同前置）。
2. **C** 可与 A 并行（文件互不重叠：`registry/` vs `store/`）。
3. **D** 待 A、C。
4. **E** 待 C；**F** 待 A、E。
5. **G1** 任意时刻；**G2** 待 C、D。

## 七、与上一条分支的关系（前置）

首个计划的产物在 `impl/auth-and-api-channel` 分支，**尚未合并**。A 之后的实施都要叠在它上面。因此：

- 写本 spec 与各子项目 spec **不受影响**；
- **开始实施 A 之前**必须先决定该分支合并回 `main` 还是保留。

本文件写在 `impl/auth-and-api-channel` 分支上，随该分支的合并决定一起落地。
