# A. 注册表补全（生成脚本）— 设计

- **日期**：2026-10-09
- **上位**：`docs/superpowers/specs/2026-10-09-后续交付路线图-design.md`（子项目 A）
- **状态**：待用户审阅
- **依据**：2026-10-09 两路只读实测普查（150 页结构普查 + YAML 字段可推导性剖析）＋ controller 复核

## 一、目标与范围

把 `src/core/registry/specs.json` 从 **11 条骨架**补到 **154 条**，并给 `EndpointSpec` 补 `params`/`responseShape`/`category`。

**交付**：
1. 生成器（抓取 + 解析 + 覆盖 + 产出 + 自检），分两个脚本；
2. `specs.json`（154 条，提交）；
3. `src/core/registry/params/*.json`（参数表与响应形状，提交）；
4. 人工 override 表（提交）；
5. 自检对账报告（写到 `registry-src/report.md`，该目录 gitignore，属开发者自查产物；**验收靠测试的不变量断言，不靠报告**）。

**不归 A**：`call()` 的 GET 分支（G1）、body 校验（B）、大规模 `envelope` 采样（D 之前可选）。

### 2.1 154 的对账（关键裁决）

```
按页面计条目：150 页 + 4 文档外 = 154
按 path 去重：132 唯一 path + 4 = 136  ✗
差额 18 = 6 组重复路径的额外页数 (9-1)+(5-1)+(3-1)+(3-1)+(2-1)+(2-1)
```

→ **注册表按页面级条目计数，绝不按 path 去重。** 同 path 的多页是**业务变体**，逐组已核实 summary：

| 共享 path | 页数 | 各页 summary（业务变体） |
|---|---:|---|
| `/` | 9 | 接收七鱼消息 / 接收会话开始通知 / …（9 个入站事件） |
| `/openapi/ipcc/calltask/add` | 5 | 分配到客服 / 分配到客服组 / 按客户关系分配 / 按自定义的客户分配 / 自动外呼任务 |
| `/openapi/message/send` | 3 | 给七鱼发送消息-文本 / 图片 / 语音 |
| `/openapi/push/msg` | 3 | 消息推送-发送文本 / 图片 / 富文本时 |
| `/openapi/ipcc/history/seat` | 2 | 呼叫坐席历史数据 / 呼叫团队历史总览数据 |

## 三、字段来源：四档（实测确定）

> 设计稿把字段来源想得比实际简单。**OpenAPI 没有 `operationId`、`info.title` 是空串**，页面编号只在 URL 里。

### 档 1 — 离线直接生成（从 YAML）

- `title` ← `paths.*.*.summary`
- `method` / `path` ← `paths` 结构
- `params` ← `parameters` + `requestBody.content.application/json.schema`，取字段名/`type`/数组元素类型/`required`/中文 `description`/`example`。**保留原始 description，不过度规范化**（枚举常只写在中文描述里，不是 `enum`）。
- `responseShape` ← `responses.*.content.*.schema`（标记为**文档声明形状**，非实测）
- `category` ← `x-apifox-folder`，并保留 `llms.txt` 层级原文（两者粒度可能冲突，见档 2）

### 档 2 — 离线出候选 → 人工 override 定稿

- `id`（见第四节规则 + override）
- `direction` / `callable`（入站页面须人工排除；`paths` 存在 ≠ 可调用）
- `auth`（**`security: []` 不得映射为 `auth: none`**；只从 `checksum` 参数存在性出候选，override 定稿）
- `maxWindowDays`（描述里 `90天`/`31天` 是**推荐值/默认值/硬上限三种语义混写**，不能自动抽）
- `category`（`x-apifox-folder` 与 `llms.txt` 层级粒度冲突）

### 档 3 — 只能人工 override

- **`dangerous`**（OpenAPI 无任何标记；写接口命名各异，不能靠关键词）
- `id` 的最终命名与冲突消解
- 异常 path 的处置（见第五节）
- `path: "/"` 的语义（入站占位符）

### 档 4 — 必须真实只读采样（红线内）

- **`envelope`**（尤其 `D` 与 `D-nf` 可能形状完全相同）
- `verified`
- 时间窗口是否真是服务端硬上限
- 空结果 / not-found / 错误码 / HTTP 状态的实际语义

→ **未采样的接口一律 `envelope: null`、`verified: false`**，不得因 YAML 里有 `code:200`/`data` 就推断成功信封。

## 四、`id` 生成规则

**规则**：`id = path 去掉 `/openapi/` 前缀、去掉 `/vN` 版本段，其余 `/` → `.`**。

- `/openapi/v2/ticket/search` → `ticket.search` ✓（与现有骨架一致）
- `/openapi/ai/knowledge/deleteKnowledges` → `ai.knowledge.deleteKnowledges` ✓
- `/openapi/message/send` → `message.send` ✓

**冲突处理**：同一 path 的多页（6 组）在 override 表里显式给出各自 id（如 `message.send` 的文本/图片/语音变体按设计稿语义命名）。**不得用中文标题拼 id。**

**不可推导的页**（`/`、中文散文 path、origin path）在 override 表里显式给 id。

→ override 的 `ids.json` 预计 **约 27 条**：6 组共享 path 的 **24 页**（推导 id 会撞）+ origin 页 2 + 中文散文页 1。`//` 折叠后 id 可由规则推导，不进 override。

## 六、产物与文件布局

```
scripts/registry/
  fetch.mjs        抓 llms.txt → 150×.md → registry-src/pages/（联网，维护者手工跑）
  generate.mjs     读 pages/ + overrides/ → 产出 specs.json + params/*.json + 对账报告
registry-src/      抓取产物（gitignore；仓库不提交第三方文档全文）
  pages/           150 个 .md 快照
  report.md        对账报告（条目数、异常、限频对齐、覆盖率）
src/core/registry/
  specs.json       154 条（提交）
  params/          每接口一文件，命名 `<id>.json`，内容 {params, responseShape}（提交，约 154 个文件）
  overrides/
    ids.json       api-xxxxx → id（约 27 条：6 组共享 path 24 页 + origin 2 + 中文散文 1）
    attrs.json     id → {direction,callable,dangerous,auth,maxWindowDays,category} override
    paths.json     异常 path 的修复规则
tests/fixtures/registry/
  pages/           覆盖全部异常形态的**样本子集**（提交，供离线测试）
```

- **依赖**：`generate.mjs` 需一个 YAML 解析器（新增 **devDependency `yaml`**；运行时零依赖不变）。脚本用 `.mjs`，`node` 直跑，不进构建、不进 npm 包。
- **不提交 150 页全文**（第三方文档、体积、开源红线）；测试用提交的**样本子集**，全量抓取是维护者步骤。
- **打包**：已核对 `package.json` 的 `files = ["dist"]` —— `scripts/`、`registry-src/`、`tests/` **自动不进包**，`dist/core/registry/params/` **自动进包**，无需改 `files`。

## 七、验收判据

1. **154 条**，`loadSpecs` 全过，且**按页面级计数**——**由测试断言证明**（`specs.length === 154`，且 id 集合覆盖 150 个 `api-xxxxx` 来源 + 4 个文档外导出接口），不依赖 gitignore 的报告。
2. **危险集合 = 16 个 id 逐条枚举**（§5.4 的 10 + 知识库 5 + `settings.wxTemplates`），不得凭推断；**任何产生副作用的写接口，在未确认为安全前一律 `dangerous: true`**（fail-closed：宁可多要一次 `--yes`，不可漏标让门禁失效）。
3. **6 类异常 path 全部按第五节处置**；`//` 折叠、去方法/origin、中文散文置 `null`。
4. **限频对账通过**：`RATE_LIMITS` 的 33 个 id 是否都在注册表里、**同 path 是否同档位**；不一致则生成器**失败并打印差异**。
5. **`auth` 不对 150 页一律填 `checksum`**：`checksum` 参数缺失的页要单独列出并人工定稿；`security: []` 不作为依据。
6. **未采样接口 `envelope: null` / `verified: false`**（生成器强制默认值，override 只能显式提升）。
7. **生成测试不联网**：以 `tests/fixtures/registry/pages/` 的样本子集跑确定性断言；抓取脚本单独测（可选，走 mock）。
8. **`params`/`responseShape` 保留原始 description**，`responseShape` 标注「文档声明形状」。
9. `npm run typecheck` / 全量测试绿（限并发）。

## 八、测试策略

- 生成器纯函数化：`parsePage(md) → RawEndpoint`、`applyOverrides(raw) → EndpointSpec`、`reconcile(specs) → Report`，各自可单测。
- 样本子集必须覆盖：普通 POST、唯一 GET、入站 `/`、`message/send` 三变体、`calltask/add` 五变体、含 `//`、含方法/origin、中文散文、`modify_cb`、以及一个 `checksum` 缺失页。
- 对账/覆盖率断言：条数、危险 16、异常 6 类、限频对齐。
- **不联网**；`fetch.mjs` 不进 CI。

## 十、非目标
