# A. 注册表补全（生成脚本）实施计划

> **交付状态**：✅ 已交付（154 条注册表 + params；`category` 的消费方由 2026-10-24 G1 批次补齐）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 `src/core/registry/specs.json` 从 11 条骨架补到 **154 条**（150 个 Apifox 文档页 + 4 个文档外会话导出接口），并为每条产出参数表与响应形状。

**Architecture:** 两个联网/离线脚本 + 三张人工 override 表。`fetch.mjs` 把 150 个文档页抓成 markdown 快照（`registry-src/`，gitignore，不进 CI）；`lib.mjs` 是纯函数层（`parsePage` → `RawEndpoint` → `fixPath`/`deriveId`/`extractParams` → `applyOverrides` → `EndpointSpec` → `reconcile` → 对账报告），**无 I/O、无网络**，测试直接 import；`generate.mjs` 只做 I/O 与编排。测试只跑提交进仓库的 **24 个样本页**，绝不联网。

**Tech Stack:** Node ≥ 20.10、ESM `.mjs`（脚本不进构建、不进 npm 包）、`yaml@2.9.1`（新增 devDependency，运行时零依赖不变）、vitest 2.1.9。

**Spec:** `docs/superpowers/specs/2026-10-09-注册表补全-design.md`（本计划实现它；执行者两份都要读）。上位路线图：`docs/superpowers/specs/2026-10-09-后续交付路线图-design.md`。

## Global Constraints

- **Node ≥ 20.10**；脚本用 `.mjs`、`node` 直跑，**不进构建、不进 npm 包**（`package.json` 的 `files` 保持 `["dist"]`）。
- **运行时零依赖不变**：`yaml` 只进 `devDependencies`。
- **仓库内全部文字用中文**（文档、注释、commit message）。**唯一例外**：标识符与接口真实返回的中文字面量（`单位时间内请求过于频繁`、`机器人答案，最大长度限制为3500字`）——逐字契约，不译。
- **跑测试必须** `npx vitest run --maxWorkers=1 --no-file-parallelism`。**禁止**任何 for/while 循环调用 vitest（2026-10-05 事故：64GB 内存耗尽，Jetsam 杀 1414 进程）。
- **只读红线**：本计划**不做任何真实 API 调用**。抓取只打 Apifox 公开文档页（纯文本 GET）。`envelope`/`verified` 只回填设计稿已记录的实测，其余留 `null`/`false`。
- **提交信息末尾**：`Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`。
- **`dangerous` 必须 fail-closed**：任何产生服务端副作用的接口，未确认为安全前一律 `true`。本计划实测审计的危险集合共 **73 个**（150 页中 72 个 + 文档外的 `export.session`；设计稿 §5.4 的枚举只是**下限**）。
- **`security: []` 不得映射为 `auth`**（实测 150/150 全空，零信息量）；`auth` 只从 `checksum` 参数存在性出候选 + override 定稿。
- **不提交 150 页全文**（第三方文档、体积、开源红线）：提交的是 24 个样本页与生成产物。

## Review Focus

设计稿是愿景文档，它对下列输入保持沉默，而沉默不是"可以崩"的许可。以下五类是执行时最可能咬人的，每一类都在本计划里有对应的测试：

1. **页面 `description` 里内嵌 ```text / ```json 围栏时** —— 非贪婪正则会在内嵌围栏处截断 YAML，解析出一个只有 3 个字段的残缺 operation，`folder`/`security`/`requestBody` 全部**静默消失**（实测 9 页如此）。→ 围栏必须锚定行首行尾（任务 2 的 `10845443` 回归用例）。
2. **`requestBody` 的 content-type 不是 `application/json` 时**（实测：form 2 页、xml 1 页、multipart 2 页、text 1 页）—— 只看 `application/json` 会把这类接口的参数表与 body 类型静默判成空/`none`。→ 必须显式分类，**未知 content-type 必须抛错**（任务 3 的 `extractParams` 用例）。
3. **override 表里写了不存在的 pageId / id 时** —— 静默忽略会让"我以为改了"与"实际没改"无法区分。→ 生成器必须抛错（任务 4 的 `validateOverrides` 用例）。
4. **同一 path 的两个页面被赋予不同限频档位时** —— 令牌桶按 path 缓存、按 id 查档位，顺序敏感。→ `reconcile` 必须失败并打印差异（任务 6）。
5. **生成产物与仓库里已提交的 `specs.json` 漂移时** —— 手改 `specs.json` 能通过测试，但下次生成会静默回退。→ 断言"重新生成 == 已提交"（任务 7 的确定性用例 + 任务 8 的 `pageId` 唯一性校验）。

## 文件结构

```
scripts/
  copy-params.mjs 把 src 的 params/ 拷进 dist（tsc 实测不拷贝未 import 的 JSON）
scripts/registry/
  fetch.mjs        联网抓 llms.txt → 150×.md → registry-src/pages/（维护者手工跑，不进 CI）
  lib.mjs          纯函数：parsePage / fixPath / deriveId / extractParams / applyOverrides / reconcile
  generate.mjs     读 pages/ + overrides/ → 产出 specs.json + params/*.json + 对账报告
registry-src/      gitignore；抓取产物（第三方文档快照，不提交）
  pages/           150 个 .md
  report.md        对账报告（开发者自查产物）
src/core/registry/
  specs.json       154 条（提交）
  params/          每接口一文件 <id>.json，内容 {params, responseShape}（提交，154 个）
  overrides/
    ids.json       pageId → id（26 条：6 组共享 path 24 页 + wecom + 客户标签变更事件）
    attrs.json     id → {direction,callable,dangerous,auth,envelope,verified,maxWindowDays,note} 人工定稿
    paths.json     不可恢复 path 的显式登记（4 条，值为 null）
tests/fixtures/registry/
  pages/           24 个样本页（提交，覆盖全部异常形态）
tests/registry/
  fixtures.test.ts 样本页本身的健全性
  lib.test.ts      parsePage / fixPath / deriveId / extractParams / applyOverrides / reconcile
  generate.test.ts 生成器端到端（用样本子集，不联网）
```

**为什么这样切**：`lib.mjs` 是纯函数层，测试不需要 mock 网络或文件系统；`generate.mjs` 只做 I/O，它的测试用样本子集跑完整流程；`fetch.mjs` 是唯一联网脚本，**不进 CI**（Apifox 站点可用性不是本项目的依赖）。

**为什么 `params/` 独立于 `specs.json`**：`api list` 只需元数据（id/title/path/dangerous/…），把 154 份参数表塞进 `specs.json` 会让它胖到几百 KB，而 Agent 读它只是为了判断"能不能调、要不要 `--yes`"。参数表是 B 子项目（请求构建）的输入，按需加载。

**为什么脚本放 `src/` 外**：`tsconfig.json` 的 `rootDir: "src"`、`files: ["dist"]` —— 放外面的脚本自动不进构建也不进包，无需改配置。

**⚠️ `params/*.json` 怎么进 `dist`**：`tsc` **只拷贝被 import 的 JSON**（`specs.json` 有 `import ... with { type: 'json' }` 所以会进 `dist`；未被 import 的 JSON 实测**不会**被拷贝）。所以在 `package.json` 加一行后处理：

```json
"scripts": {
  "build": "tsc && node scripts/copy-params.mjs"
}
```

```js
// scripts/copy-params.mjs
// tsc 不拷贝未被 import 的 JSON（实测），生成的 params/*.json 必须手动进 dist。
// ⚠️ 必须容忍 src 侧 params/ 尚不存在 —— 首次 build 发生在生成器跑之前
// （生成器又要先要 dist/core/ratelimit.js，形成先后依赖），此时静默跳过。
import { cp, mkdir, access } from 'node:fs/promises'
try {
  await access('src/core/registry/params')
} catch {
  console.log('params/ 尚未生成（首次 build），跳过拷贝 —— 生成后重跑 npm run build')
  process.exit(0)
}
await mkdir('dist/core/registry', { recursive: true })
await cp('src/core/registry/params', 'dist/core/registry/params', { recursive: true })
```

```js
// scripts/registry/fetch.mjs
// 联网抓取 Apifox 公开文档页。**不进 CI** —— Apifox 站点可用性不是本项目的依赖。
// 用法：node scripts/registry/fetch.mjs [输出目录]（默认 registry-src/pages/，已 gitignore）
import { mkdir, writeFile } from 'node:fs/promises'
import { join } from 'node:path'

const INDEX_URL = 'https://qiyukf.apifox.cn/llms.txt'

/** 从 llms.txt 提取全部 api-*.md 的 URL，去重后按出现顺序返回。 */
export async function listPageUrls(fetchImpl = fetch) {
  const text = await (await fetchImpl(INDEX_URL)).text()
  const urls = []
  const seen = new Set()
  for (const m of text.matchAll(/https:\/\/qiyukf\.apifox\.cn\/api-\d+\.md/g)) {
    if (seen.has(m[0])) continue
    seen.add(m[0])
    urls.push(m[0])
  }
  return urls
}

/** 抓一个页面并写到 outDir/<basename>。返回写入的文件名。 */
export async function fetchPage(url, outDir, fetchImpl = fetch) {
  const name = url.split('/').pop()
  const res = await fetchImpl(url)
  if (!res.ok) throw new Error(`抓取 ${url} 失败：HTTP ${res.status}`)
  await writeFile(join(outDir, name), await res.text(), 'utf8')
  return name
}

/** 抓全部页面。默认并发 6（Apifox 是静态站）。 */
export async function fetchAll(outDir = 'registry-src/pages', fetchImpl = fetch, concurrency = 6) {
  await mkdir(outDir, { recursive: true })
  const urls = await listPageUrls(fetchImpl)
  let fetched = 0
  for (let i = 0; i < urls.length; i += concurrency) {
    const names = await Promise.all(urls.slice(i, i + concurrency).map((u) => fetchPage(u, outDir, fetchImpl)))
    fetched += names.length
  }
  return { total: urls.length, fetched }
}

// 直接运行时才执行（被 import 时不跑）
if (import.meta.url === `file://${process.argv[1]}`) {
  const outDir = process.argv[2] ?? 'registry-src/pages'
  const r = await fetchAll(outDir)
  console.log(`抓取完成：${r.fetched}/${r.total} 个页面 → ${outDir}/`)
}
```

import { describe, it, expect } from 'vitest'
import { readFileSync } from 'node:fs'
import { parsePage } from '../../scripts/registry/lib.mjs'

// ⚠️ 用 URL 定位 fixture（`import.meta.dirname` 要 Node ≥ 20.11，engines 是 >=20.10；
// readFileSync 本就接受 file:// URL）
const pageUrl = (id: string) => new URL(`../fixtures/registry/pages/api-${id}.md`, import.meta.url)
const load = (id: string) => readFileSync(pageUrl(id), 'utf8')

describe('parsePage', () => {
  it('普通 POST：summary 作 title、path 原样、folder 取 x-apifox-folder 的完整层级', () => {
    const r = parsePage(load('10845434'), 'api-10845434')
    expect(r.title).toBe('获取SDK接入地址')
    expect(r.method).toBe('POST')
    expect(r.path).toBe('/openapi/staff/login')
    expect(r.folder).toBe('通用说明/服务端登录')
    expect(r.pageId).toBe('api-10845434')
  })

  it('唯一 GET 接口：method 归一为大写 GET', () => {
    const r = parsePage(load('10845435'), 'api-10845435')
    expect(r.method).toBe('GET')
    expect(r.path).toBe('/get_token')
    expect(r.folder).toBe('CRM 对接/CRM 接口对接')
  })

  it('params 含 query 与 body 字段（body 取 requestBody 里第一个 content 的 schema）', () => {
    const r = parsePage(load('10845572'), 'api-10845572')
    const q = r.params.filter((p) => p.in === 'query')
    expect(q.map((p) => p.name)).toEqual(['appKey', 'time', 'checksum'])
    expect(q.every((p) => p.required)).toBe(true)
    const body = r.params.filter((p) => p.in === 'body')

    // 三个键的残缺 operation —— folder/security/requestBody 全部静默消失。
    const r = parsePage(load('10845443'), 'api-10845443')
    expect(r.folder, 'folder 丢失 = YAML 被截断').toBe('客户管理/客户标签')

  })

    const r = parsePage(load('10845543'), 'api-10845543')
    expect(r.params.map((p) => p.name)).toEqual(['robotId'])

```js
// scripts/registry/lib.mjs
// 注册表生成器的纯函数层：**无 I/O、无网络**，测试直接 import。
// ⚠️ 这是 .mjs 但被 .ts 测试 import —— vitest 原生支持；`npm run typecheck` 需要
//    tsconfig.test.json 打开 allowJs。
import { parse as yamlParse } from 'yaml'

/**
 * @typedef {Object} ParamSpec
 * @property {string} name
 * @property {'query'|'header'|'body'|'path'} in
 * @property {boolean} required
 * @property {string} type
 * @property {string} description
 * @property {string} [example]
 */

/**
 * @typedef {Object} RawEndpoint
 * @property {string} pageId
 * @property {string} title
 * @property {'POST'|'GET'} method
 * @property {string} path
 * @property {string|null} folder
 * @property {ParamSpec[]} params
 * @property {{kind:'object'|'array'|'primitive'|'none', description?:string}} responseShape
 * @property {unknown[]} security
 * @property {Record<string, any>} op  原始 OpenAPI operation（extractParams 要看 content-type）
 */

/**
 * 从页面 markdown 抽出 OpenAPI 的 ```yaml 围栏块。
 *
 * ⚠️ **必须锚定到行首行尾**（`^```$`，带 m 标志）。页面的 `description` 里内嵌
 * ```text / ```json 围栏（实测 9 页如此），用非贪婪的 /^```yaml\n([\s\S]*?)```/
 * 会停在**内嵌围栏的结束行**，解析出只剩 3 个键的残缺 operation ——
 * `x-apifox-folder`、`security`、`requestBody` 全部消失，**且不报错**。
 */
function extractYaml(md) {
  const m = /^```yaml\n([\s\S]*?)^```$/m.exec(md)
  if (!m) throw new Error('页面缺 ```yaml 块')
  return m[1]
}

/** 把 OpenAPI 的 parameters 数组项转成 ParamSpec。 */
function toParamSpec(p) {
  const schema = p.schema ?? {}
  return {
    name: p.name,
    in: p.in,
    required: !!p.required,
    type: schema.type ?? 'string',
    description: p.description ?? '',
    ...(p.example !== undefined ? { example: String(p.example) } : {}),
  }
}

/** requestBody 里第一个 content 的 schema（每页实测恰好 0 或 1 种 content-type）。 */
function firstBodySchema(op) {
  const content = op?.requestBody?.content ?? {}
  return Object.values(content)[0]?.schema ?? null
}

/**
 * 从一个 Apifox 页面 markdown 解析出 RawEndpoint。**同步**（yaml 是顶层 import）。
 *
 * ⚠️ `paths` 键数必须恰好为 1：0 条（`paths: {}`）或多条时抛错，而不是静默取第一条。
 * ⚠️ method 必须是 POST 或 GET：150 页实测只有这两种，出现别的说明页面结构变了。
 */
export function parsePage(md, pageId) {
  const doc = yamlParse(extractYaml(md))

  const pathKeys = Object.keys(doc.paths ?? {})
  if (pathKeys.length !== 1) {
    throw new Error(`${pageId}: paths 键数 ${pathKeys.length} ≠ 1 —— 无法确定该页对应哪个接口`)
  }
  const path = pathKeys[0]
  const methods = Object.keys(doc.paths[path] ?? {})
  if (methods.length !== 1) {
    throw new Error(`${pageId}: path ${path} 上有 ${methods.length} 个 method —— 预期 1 个`)
  }
  const method = methods[0].toUpperCase()
  if (method !== 'POST' && method !== 'GET') {
    throw new Error(`${pageId}: 意外 method ${method} —— 150 页实测只有 POST/GET`)
  }
  const op = doc.paths[path][methods[0]]

  const params = (op.parameters ?? []).map(toParamSpec)
  const body = firstBodySchema(op)
  for (const [name, schema] of Object.entries(body?.properties ?? {})) {
    params.push({
      name,
      in: 'body',
      required: (body.required ?? []).includes(name),
      type: schema.type ?? 'string',
      description: schema.description ?? '',
      ...(schema.example !== undefined ? { example: String(schema.example) } : {}),
    })
  }

  const resp = op.responses?.['200']?.content?.['application/json']?.schema
  const rt = resp?.type
  const responseShape = resp
    ? { kind: rt === 'array' ? 'array' : rt === 'object' || rt === undefined ? 'object' : 'primitive',
        ...(resp.description ? { description: resp.description } : {}) }
    : { kind: 'none' }

  return {
    pageId,
    title: op.summary ?? /^# (.+)$/m.exec(md)?.[1] ?? '',
    method,
    path,
    folder: op['x-apifox-folder'] ?? null,
    params,
    responseShape,
    security: doc.security ?? [],
    op,
  }
}
```

```js
const BODY_KINDS = {
  'application/json': 'json',
  'application/x-www-form-urlencoded': 'form',
  'multipart/form-data': 'multipart',
  'application/xml': 'xml',
  'text/plain': 'text',
}

/**
 * 判定 requestBody 的种类。
 *
 * ⚠️ 实测 150 页里 body 有 6 种形态（json 138 / 无 requestBody 6 / form 2 /
 * multipart 2 / xml 1 / text 1）。**未知 content-type 必须抛错** —— 静默归为
 * `none` 会让一个"参数在别的 content-type 里"的接口看起来像没有 body。
 *
 * @param {import('./lib.mjs').RawEndpoint} raw
 */
export function extractParams(raw) {
  const content = raw.op?.requestBody?.content ?? {}
  const types = Object.keys(content)
  if (types.length === 0) return { params: raw.params, bodyKind: 'none' }
  if (types.length > 1) {
    throw new Error(`${raw.pageId}: requestBody 有 ${types.length} 种 content-type（${types.join(', ')}）—— 实测每页只有 0 或 1 种`)
  }
  const bodyKind = BODY_KINDS[types[0]]
  if (!bodyKind) {
    throw new Error(`${raw.pageId}: 未知 requestBody content-type「${types[0]}」—— 不得静默当作 none`)
  }
  return { params: raw.params, bodyKind }
}

/**
 * 修复文档页里畸形的 path。
 *
 * ⚠️ 判定**有次序**：`method-origin` 必须排在"含空白即散文"之前 ——
 * origin 形态的 path（`/POST https://…`）本身就含空格，先判散文会把它误杀成 null。
 *
 * 规则（实测清单，设计稿 §5）：
 * - `/`            → 原样（入站占位符，是合法 path，不是异常）
 * - `/{…}`         → null（模板占位符，真实路径由调用方运行时决定）
 * - `//…`          → 折叠为单斜杠
 * - `/<METHOD> <URL>` → 取 URL 的 pathname
 * - 含空白或汉字    → null（中文散文，不可恢复）
 * - `/openapi/openapi/…` → 折叠重复前缀
 */
export function fixPath(path) {
  if (path === '/') return { path: '/', rule: null }
  if (path.startsWith('/{')) return { path: null, rule: 'placeholder' }
  if (path.startsWith('//')) return { path: path.replace(/\/{2,}/g, '/'), rule: 'double-slash' }
  const mo = /^\/(GET|POST|PUT|DELETE|PATCH|HEAD|OPTIONS)\s+(https?:\/\/\S+)$/.exec(path)
  if (mo) return { path: new URL(mo[2]).pathname, rule: 'method-origin' }
  if (/[\s\p{Script=Han}]/u.test(path)) return { path: null, rule: 'prose' }
  if (!path.startsWith('/')) return { path: null, rule: 'prose' }
  if (path.startsWith('/openapi/openapi/')) {
    return { path: path.replace(/^\/openapi\/openapi\//, '/openapi/'), rule: 'double-openapi' }
  }
  return { path, rule: null }
}

/**
 * 从（已修复的）path 派生 id。派生不出合法 id 时返回 null —— 该页必须由
 * `ids.json` 显式给 id，生成器对 null 抛错（不静默丢接口）。
 *
 * 规则：剥 `/platform/api/openapi/` 或 `/openapi/` 前缀 → 剥开头的 `/vN/` →
 * 其余 `/` 换成 `.`。安全性由白名单字符集兜底：出现 `{`、汉字、空格等即拒绝。
 */
export function deriveId(path) {
  if (!path) return null
  const p = path
    .replace(/^\/platform\/api\/openapi\//, '/')
    .replace(/^\/openapi\//, '/')
    .replace(/^\/v\d+\//, '/')
    .replace(/^\//, '')
    .split('/')
    .join('.')            // ⚠️ 少了这两行，`ticket/search` 连白名单都过不了 → 恒 null
  if (!/^[A-Za-z][A-Za-z0-9_]*(?:\.[A-Za-z0-9_]+)*$/.test(p)) return null
  return p
}
```

```js
const ENVELOPES = ['A', 'B', 'C', 'D', 'D-nf']

/**
 * 校验三张 override 表与当前页面集合一致。**未知键一律抛错** —— 静默忽略
 * 会让"我以为改了"与"实际没改"无法区分，而那正是本计划要消灭的形态。
 *
 * @param {{ids:Record<string,string>, paths:Record<string,string|null>, attrs:Record<string,object>}} tables
 * @param {Set<string>} knownPageIds
 * @param {Set<string>} [knownIds] 已知 id（默认只校验 attrs 的 envelope/verified 形状）
 */
export function validateOverrides(tables, knownPageIds, knownIds) {
  for (const [pageId, id] of Object.entries(tables.ids ?? {})) {
    if (!knownPageIds.has(pageId)) throw new Error(`ids.json 含未知 pageId：${pageId}`)
    if (typeof id !== 'string' || !id) throw new Error(`ids.json[${pageId}] 的 id 必须是非空字符串`)
  }
  for (const [pageId, p] of Object.entries(tables.paths ?? {})) {
    if (!knownPageIds.has(pageId)) throw new Error(`paths.json 含未知 pageId：${pageId}`)
    if (p !== null && (typeof p !== 'string' || !p.startsWith('/'))) {
      throw new Error(`paths.json[${pageId}] 只能是 null 或以 / 开头的字符串`)
    }
  }
  for (const [id, a] of Object.entries(tables.attrs ?? {})) {
    if (knownIds && !knownIds.has(id)) throw new Error(`attrs.json 含未知 id：${id}`)
    if (a.envelope !== undefined && a.envelope !== null && !ENVELOPES.includes(a.envelope)) {
      throw new Error(`attrs.json[${id}] 的 envelope 非法：${a.envelope}`)
    }
    if (a.envelope !== undefined && a.envelope !== null && a.verified !== true) {
      throw new Error(`attrs.json[${id}] 登记了 envelope 却未标 verified:true —— 没实测过就不该登记形状`)
    }
  }
}
```

```js
/** EndpointSpec 的字段顺序 —— 固定顺序才有稳定的 diff。 */
const FIELD_ORDER = ['id','pageId','title','method','path','direction','callable','dangerous',
                     'auth','verified','envelope','maxWindowDays','category','note']

/**
 * 把一个 RawEndpoint 合成为注册表条目。
 *
 * **默认值刻意选成 fail-closed 的那一侧**：`dangerous:true`、`auth:'checksum'`、
 * `envelope:null`、`verified:false`。人工 override 只能把它们往"更宽松"改，
 * 且每一处放宽都在 attrs.json 里有据可查。
 *
 * @param {import('./lib.mjs').RawEndpoint} raw
 * @param {{ids:Record<string,string>, paths:Record<string,string|null>, attrs:Record<string,object>}} tables
 * @param {Set<string>} [usedIds] 已占用的 id（用于冲突检测）
 */
export function applyOverrides(raw, tables, usedIds = new Set()) {
  const fixed = tables.paths && Object.hasOwn(tables.paths, raw.pageId)
    ? { path: tables.paths[raw.pageId], rule: 'override' }
    : fixPath(raw.path)

  const id = tables.ids?.[raw.pageId] ?? deriveId(fixed.path)
  if (!id) throw new Error(`${raw.pageId}: 派生不出 id，且 ids.json 未显式给出`)
  if (usedIds.has(id)) throw new Error(`id 冲突：${id} 被 ${raw.pageId} 与另一页共用 —— 共享 path 必须显式命名`)
  usedIds.add(id)

  const a = tables.attrs?.[id] ?? {}
  const direction = a.direction ?? 'outbound'
  const callable = a.callable ?? (direction === 'outbound' && fixed.path !== null)
  // ⚠️ fail-closed：不给 danger 就是 true。设计稿 §5.4 的 16 条是下限不是全部。
  const dangerous = a.dangerous ?? true
  const auth = a.auth ?? 'checksum'
  const verified = a.verified ?? false
  const envelope = a.envelope ?? null

  const spec = {
    id,
    pageId: raw.pageId,
    title: a.title ?? raw.title,
    method: raw.method,
    path: fixed.path,
    direction,
    callable,
    dangerous,
    auth,
    verified,
    envelope,
    ...(a.maxWindowDays !== undefined ? { maxWindowDays: a.maxWindowDays } : {}),
    category: a.category ?? raw.folder,
    ...(a.note !== undefined ? { note: a.note } : {}),
  }
  return { spec: orderFields(spec), params: extractParams(raw).params, bodyKind: extractParams(raw).bodyKind }
}

/** 按 FIELD_ORDER 重排键（未列出的键排在其后，保持相对顺序）。 */
function orderFields(obj) {
  const out = {}
  for (const k of FIELD_ORDER) if (k in obj) out[k] = obj[k]
  for (const k of Object.keys(obj)) if (!(k in out)) out[k] = obj[k]
  return out
}
```

/**
 * 对账，产出自查报告与错误列表。`errors` 非空时生成器必须失败退出。
 *
 * ⚠️ 第 ② 项是**回归哨兵**：`RATE_LIMITS` 是手工表，注册表是生成的，两者靠 id
 * 对齐。生成脚本补齐 specs.json 时若忘了同步限频表 id，这里会拦下 —— 而不是
 * 让限频层静默失效（`limitFor` 查不到就返回 null = 不限频）。
 */
export function reconcile(specs, rateLimits) {
  const errors = []
  const lines = []

  // ① 同一 path 上所有 id 的限频必须一致
  const byPath = new Map()
  for (const s of specs) {
    if (!s.path) continue
    byPath.set(s.path, [...(byPath.get(s.path) ?? []), s])
  }
  let sharedPaths = 0
  for (const [path, group] of byPath) {
    if (group.length < 2) continue
    sharedPaths++
    const tiers = new Set(group.map((s) => JSON.stringify(rateLimits[s.id] ?? null)))
    if (tiers.size !== 1) {
      errors.push(`同 path 限频不一致：${path} ← ${group.map((s) => s.id).join(', ')}`)
    }
  }

  // ② RATE_LIMITS 的每个键都能在注册表里找到 id
  const ids = new Set(specs.map((s) => s.id))
  const orphans = Object.keys(rateLimits).filter((k) => !ids.has(k))
  if (orphans.length) errors.push(`RATE_LIMITS 的 id 不在注册表里：${orphans.join(', ')}`)

  // ③ 计数
  const dangerous = specs.filter((s) => s.dangerous).length
  const inbound = specs.filter((s) => s.direction === 'inbound').length
  const measured = specs.filter((s) => s.envelope !== null).length
  lines.push(`# 对账报告`, '',

```js
// scripts/registry/generate.mjs
// 读 registry-src/pages/*.md + overrides/ → 产出 specs.json + params/*.json + report.md
// 用法：node scripts/registry/generate.mjs   （在仓库根跑；先 npm run build 让 dist 就绪）
import { readFileSync, readdirSync } from 'node:fs'
import { mkdirSync, writeFileSync } from 'node:fs'
import { join } from 'node:path'
import { parsePage, applyOverrides, validateOverrides, reconcile, deriveId, fixPath } from './lib.mjs'

const PAGES_DIR = 'registry-src/pages'
const OUT_DIR = 'src/core/registry'
const OVERRIDES_DIR = 'src/core/registry/overrides'
const REPORT = 'registry-src/report.md'

/** 4 个文档外接口（会话导出流水线，设计稿 §7.5，150 页里 0 命中）。 */
const EXTERNAL_ENDPOINTS = [
  { id: 'export.session',             title: '创建会话导出任务', method: 'POST', path: '/openapi/export/session' },
  { id: 'export.session.check',       title: '查询会话导出任务', method: 'POST', path: '/openapi/export/session/check' },
  { id: 'export.session.one',         title: '单条会话查询',     method: 'POST', path: '/openapi/export/session/one' },
  { id: 'export.session.one.message', title: '单条会话消息查询', method: 'POST', path: '/openapi/export/session/one/message' },
]

export async function generate({
  pagesDir = PAGES_DIR, outDir = OUT_DIR, overridesDir = OVERRIDES_DIR,
  reportPath = REPORT, rateLimits,
} = {}) {
  const read = (p) => JSON.parse(readFileSync(p, 'utf8'))
  const ids = read(join(overridesDir, 'ids.json'))
  const attrs = read(join(overridesDir, 'attrs.json'))
  const paths = read(join(overridesDir, 'paths.json'))
  const tables = { ids, attrs, paths }

  const files = readdirSync(pagesDir).filter((f) => f.endsWith('.md')).sort()
  const raws = files.map((f) =>
    parsePage(readFileSync(join(pagesDir, f), 'utf8'), f.replace(/\.md$/, '')))

  // knownIds = ids.json 显式给的 + 各页（修复 path 后）派生的 + 4 个文档外
  const knownIds = new Set([
    ...Object.values(ids),
    ...raws.map((r) => ids[r.pageId] ?? deriveId(fixPath(r.path).path)),
    ...EXTERNAL_ENDPOINTS.map((e) => e.id),
  ])
  validateOverrides(tables, new Set(raws.map((r) => r.pageId)), knownIds)

  const usedIds = new Set()
  const specs = []
  const paramsById = {}
  for (const raw of raws) {
    const { spec, params, bodyKind } = applyOverrides(raw, tables, usedIds)
    specs.push(spec)
    paramsById[spec.id] = { params, responseShape: raw.responseShape, bodyKind }
  }
  for (const e of EXTERNAL_ENDPOINTS) {
    if (usedIds.has(e.id)) throw new Error(`id 冲突：文档外接口 ${e.id} 与某页撞名`)
    usedIds.add(e.id)
    const a = attrs[e.id] ?? {}
    const spec = {
      id: e.id, title: e.title, method: e.method, path: e.path,
      direction: a.direction ?? 'outbound',
      callable: a.callable ?? true,
      dangerous: a.dangerous ?? true,          // export.session 会创建导出任务 → fail-closed
      auth: a.auth ?? 'checksum',
      verified: a.verified ?? false,
      envelope: a.envelope ?? null,
      ...(a.maxWindowDays !== undefined ? { maxWindowDays: a.maxWindowDays } : {}),
      ...(a.category !== undefined ? { category: a.category } : {}),
      ...(a.note !== undefined ? { note: a.note } : {}),
    }
    specs.push(spec)
    paramsById[e.id] = { params: [], responseShape: { kind: 'none' }, bodyKind: 'none' }
  }

  specs.sort((x, y) => (x.id < y.id ? -1 : x.id > y.id ? 1 : 0))

  mkdirSync(join(outDir, 'params'), { recursive: true })
  writeFileSync(join(outDir, 'specs.json'), JSON.stringify(specs, null, 2) + '\n')
  for (const [id, body] of Object.entries(paramsById)) {
    writeFileSync(join(outDir, 'params', `${id}.json`), JSON.stringify(body, null, 2) + '\n')
  }

  let rl = rateLimits
  if (rl === undefined) {
    ;({ RATE_LIMITS: rl } = await import('../../dist/core/ratelimit.js'))
  }
  const { report, errors } = reconcile(specs, rl)
  writeFileSync(reportPath, report)
  return { specs, report, errors }
}

if (import.meta.url === `file://${process.argv[1]}`) {
  const { errors } = await generate()
  if (errors.length) { console.error(errors.join('\n')); process.exit(1) }
  console.log('生成完成 → src/core/registry/{specs.json,params/}')
}
```

> **文档外 4 条不带 `pageId`** —— `loadSpecs` 的 `pageId` 校验是 `!== undefined` 才查，页面级计数（150）靠"有 `pageId` 的条数"得出。
