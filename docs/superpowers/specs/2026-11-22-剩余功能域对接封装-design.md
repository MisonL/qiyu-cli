## 2. P0 · Windows 凭证权限：证据链与裁决

### 2.1 三层失效（【已验证】，静态 + 真机）
- **写入不收紧**：`writeConfigFile`（`src/core/config.ts:545-561`）在 win32 上 `mkdir mode:0o700`「Not supported on Windows」、`writeFileSync{mode:0o600}` + `chmodSync(0o600)` 只映射「只读属性」——**NTFS DACL 零改变**。
- **门禁不拦截**：`checkPermissions:371` 首行 `if (process.platform === 'win32') return {ok:true}`，「含凭证过宽即拒绝」在 Windows 上整条蒸发（连警告都没有）。
- **自检恒 ok**：`auth login` 写后自检调 `checkPermissions`（`auth.ts` 的「权限自检」段），win32 短路使它在 Windows 上 **恒返回 ok**——`configured:true` 里的「权限已复核」这层含义在 Windows 上没有发生；而同一函数上方的注释把 「凭证已落盘且可被他人读却报成功」定义为假成功，win32 路径恰好落进自己定义的形态。 · **边界澄清（Codex P1-4）**：自检的 `catch { }` 吞错是**另一件事**——它对全平台一致、注释写明是有意的 （「自检失败不影响已写入这一事实；下一次任何命令都会再查一次」），不是 win32 特有。 spec 此前把两者压成 「自检恒真」一句，读起来像 catch 也是 win32 分支——修法里两者要分开对待。- **影响面（按调用链列，Codex P1-4 要求）**：`writeConfigFile` 的直接写入方只有 `auth login`；`checkPermissions` 直接调用点三处 （login 自检、`loadConfigChecked`、`store/config.ts resolveStoreConfig`），传递覆盖 `auth whoami`、`api call`、 `sync run/status/verify/install/uninstall`、`store/db/query/stats` 全族与限流 fallback 探测；`api list`/`api schema`/ `skill *`/`--version` 不读配置，不在其内。

### 2.2 真机决定性证据（M1 + 我亲自复核 T-8/T-7a）
- **M1（有效证据）**：Windows 上 0600/0644/0666 四种造法的文件，`icacls` 输出**逐字节相同**、`statSync().mode` 全部回读 `666`；把 config.json 显式 `/grant` 给 `Everyone:(R)` + `BUILTIN\Users:(R)`（**RC=0、ACE 在、含凭证**）后 `auth whoami` **RC=0** 照常返回 `configured:true`，不报 `config_insecure`；`icacls /reset` 回纯继承后仍 RC=0。
- **T-8**：git 历史证明两个函数自 `5650cfa`(G1/v0.2.0) 引入、v0.2.1→v0.2.3 函数体哈希相同 ——「非 0.2.2 回归」 **这一半是源码历史可复核的**；另 一 半 「三版产物在 Windows 上 ACL 逐字节相同」只是**本机样本观察** （原始输出见 `private/evidence/2026-11-22-windows-acl/raw-outputs.md`，gitignored），不推广为普遍结论。该缺陷是 **G1（PR #13，v0.2.0 起）的存量**，0.2.2 在权限域反而往诚实方向走（新增 ACL 拒绝的平台分流）。用户「0.2.2 起」是观测时点，不是回归点。
- **T-7a（精确归因）**：M1 环境中那条**测试机特有的某沙箱服务组**的 `(I)(M,DC)` ACE 来自 `%TEMP%` 目录本身（新建任意文件都继承），**不是 qiyu 写入的、也不是全体登录用户可读**。真实暴露面按「NTFS 默认 ACL 可能授予广域主体 + CLI 不检查也不告警」陈述，**不夸大**成「所有登录用户可读」。
- **T-8 附加**：Windows上 `os.homedir()` 只认 `USERPROFILE`（HOME 完全忽略）；OpenSSH 会话里 `USERPROFILE` 指向 Temp——路径契约在 Windows 上比预想复杂。
- **我方探针诚实记录**：我自己跑的一轮「放宽 Everyone 后 whoami rc=0」是**无效探针**（凭证从 env 读、`grant` 静默失败、ACE 没落上）；「门禁不拦」只以 M1 那份有效证据为准。

### 2.3 Linux 正确基线（M2，全实测）
文件 600 / 目录 700 且与 umask 077/022/**000** 无关；644 → whoami rc=1 `config_insecure` + `chmod 600` hint；目录 757/777 → 拦、755 不拦（判据 `&0o022`）；把 login 产物复制成 644 后 `nobody` 真能读出 secret（泄露面真实）；644 下 `login` 静默自愈为 600、777 目录下 login 报「已写入但自检不合格」；符号链接**只写侧拒绝、读侧跟随**。

### 2.4 修法（两阶段，A 未实测前不写 README 承诺）
1. **方案 B（立即，低成本诚实）**：README(:122、:176-193)、design(:169/:185)、`errors.md` ①档、`auth login` help/field_notes、`writeConfigFile` 注释统一收窄为「POSIX 域承诺；Windows 上 mode 不落 ACL、CLI 不检查也不告警，暴露面由 NTFS 默认 ACL 决定，需人工 `icacls`」；把无条件 `statSync().mode & 0o777` 断言逐处平台化（清点：`tests/core/config.test.ts:283,284,295,302` + `tests/commands/auth.test.ts:237,238` 共 6 处，另有两文件各自的 `writeCfg(mode=0o600)` 夹具默认值）。
2. **方案 A（以真机为闸）**：写入侧 win32 显式 `icacls /inheritance:r /grant:r "<当前用户 SID>:(R,W)"`（按 **SID** 不是本地化 trustee 名——同「按错误文本分流」红线）；`checkPermissions` win32 分支改**真探测 ACL**，返回三态 `{ok:true, checked:true|false}`，三个调用点（`auth.ts:317`、`loadConfigChecked:334`、`store/config.ts:116`）把「判定不了」如实透出；不得复用 `mode & 0o077` 判据（Windows 正常文件回读 666，会把所有人误拒）。非 NTFS / icacls 不可用 → 「判定不了」，不冒认 ok。
3. **同构面裁决**：`store init` 创建的 DuckDB 库文件（含业务数据）同样无权限收紧——要明确「一并收口」还是「明确非目标并声明」，不留下沉默缺口。

### 2.4b 平台假设清单（Codex P1-6 指出原文穷举不全，补全）每项标「静态推断 / 隔离探针 / 真机已验」，不混用：- **凭证文件 ACL**：win32 短路恒绕过 + mode 不落 DACL ——真机已验（M1/T-7a/T-8 本机样本）。- **时钟校准 hint**（`errors.ts:303-306`）：只给 macOS `sntp` 与 Linux `timedatectl/ntpdate`，**无 Windows 分支** （`w32tm / resync` 缺失）——静态已证，属「hint 指向不可执行动作」形态，**待修**。- **junction 的 lstat 形态**：`skill/paths.ts` 自述未实测；`config.ts` 的符号链接拒绝只在 macOS 真机验过 ——静态推断。- **systemd unit 与 schtasks /TR 执行模型**：`schedule/install.ts` 注释自述依据文档推断、无端到端验收 ——静态推断。- **PowerShell/cmd 引号方言**：`shellArg` 已分平台并有守卫，但未在 Windows 真机跑过端到端 ——静态推断。- **DuckDB 锁报文**：Linux 锁报文缺 ` by user ` 段的历史教训在案，判据已跨平台实测 ——真机已验。- **业务数据文件（DuckDB 库）权限**：`store init` 创建的库文件同样无收紧，与凭证同构——静态已证，修法待裁。### 2.5 回归防线

## 4. P1/P2 各域结论摘要

### §2 工单/知识库只读语义族（R3）
- **纠正前提**：§2 状态注早在 `691c59d`(PR #50) 回写、`docs.test.ts:710+/850+` 双向钉死——**是如实挂账，不是悬空承诺**。我此前说法有误，已纠正。

- 语义层的增量价值仅两处：①把只在 sync 任务里存在的**强制护栏**（`opEnd=0` 全量陷阱、`robotId` 静默忽略、相似问 id 静默空返回）带给实时通道；②多端点实时编排。**历史数据已由 `query --table` 覆盖**，否则语义命令就是「第三条没人用的入口」。

- 集成面 9 处机器守卫同批改（command-tree `toEqual` 精确数组、README 双向表、反向图例元素级、docs.test 的 §2 状态注**同 PR 反转**、skill 路由表…）；只读族不需要 `--yes`（门禁唯一判据 `spec.dangerous && !confirmed`）。
- 档位：中（≈E 的 1/3–1/2）。建议最小集 `kb search/detail/categories`；工单族除非拿到 Agent 实时踩坑证据，先按非目标收口。

### C2 外部后端（R1）
- 写路径 `Store` 抽象 + `BACKENDS` 工厂是干净扩展点；**读路径三层沙箱、脱敏词法、错误翻译、元数据探测全部硬编码 DuckDB 且刻意不经 Store**（E spec 原文理由）。只加 `BackendName` 成员而不做读路径闸门 = `--backend postgres` 静默按 DuckDB 开文件的假能力，违红线。
- 用户此前裁决「不启动」。启动前需撤销，并按 C2-core(SQLite 写+全仓诚实性闸门, 中) → C2-read(沙箱等效, 大) → C2-pg → C2-mysql(方言缺口最多) 四段独立 spec。
- Linux 机可验：真服务器错误报文锚点、upsert/迁移方言、并发矩阵、三层沙箱穿透攻击集、BIGINT 序列化差异。需预置 PG/MySQL 实例 + 专用测试库 + 最小权限角色；账号连接串只走环境变量/`private/`。

### 工单写命令族 + §9.4 名称解析（R2）
- 10 条 ticket 写端点**全 `dangerous:true` / `verified:false` / `envelope:null`**，全仓零生产调用方（只有注释与测试清单引用）——纯契约裸奔；读侧链路（search/log/templates/staff 维表）反而齐备。
