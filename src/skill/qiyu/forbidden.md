# 禁止事项

这些禁令每一条都对应一类真实事故：静默失败、重复执行、数据泄露或把不成熟的能力当工具。

## 1. 不要读配置文件

`~/.config/qiyu/config.json` 属于人类维护面：凭证与存储行为都由它（或环境变量）决定，
CLI 对未知键 fail-closed 校验。读它没有收益——它决定的一切都能用命令与 flag 自描述获得：
需要知道库路径与后端时用 `qiyu store status`（它的输出里**不含 profile**）。profile 与
`--db` / `--backend` 一样是定位参数：给名字，交给命令自己解析成实际的库路径与后端。
需要知道凭证状态时用 `qiyu auth whoami`。不要 cat、grep 或解析该文件，也不要把它的内容
写进任何输出或日志。

## 2. 不要使用 `--pretty`

`--pretty` 是「承诺过、未实现」的 flag：CLI 只输出紧凑 JSON（一行、stdout、可解析）。
不要求美化的输出格式；要读字段就按 JSON 解析。当前每一族命令都会以「尚未实现」显式拒绝它。

## 3. 不要盲目重试

按 `errors.md` 的 kind 表决定动不动作：

- `retryable: false` 的错误（参数错、权限、用法错、需要确认）重试是浪费——先修成因。
- 危险操作（写接口）重试可能重复执行——没有人类明确同意，绝不重试。
- 退避重试时用有限次数与递增间隔；循环撞限流只会让冷却更长。

## 4. 不要拿 `--sql` 跑单表简单过滤

`qiyu query --table <表>` 是单表查询的**默认通道**：表名闭集校验、时间过滤、分组计数、
按列声明的精确脱敏。`qiyu query --sql <SQL>` 是给 JOIN、跨表聚合等受约束通道表达不了的场景的。

用 `--sql` 跑 `--table` 能表达的查询，等于自己放弃列白名单与精确脱敏——多读出的敏感列
会直接进你的上下文与日志。判断标准：如果查询只需要一张表加过滤/分组，用 `--table`。

## 5. 不要在确认新鲜度前下结论

先看 `qiyu sync status` 的水位与覆盖区间，再看查询 meta 的 `resolved_range` 与
`data_coverage`；两者对不上时（例如报表截止昨天而任务水位停在前天）如实说明。
没有新鲜度证据的结论，在人类眼里就是「可能是旧数据」——与其被追问，不如一开始就写清。

## 6. 其他硬性红线

- **不要猜测表名、列名、接口 id**：一律 `qiyu db tables` / `qiyu db describe <表>` /
  `qiyu api list` 先查。名字是闭集，猜错的代价是静默失败。
- **不要关闭脱敏后把输出写进日志或对外报表**：`--no-mask` 只用于人类明确要求的临时排查，
  输出不得落盘、不得转发。
- **不要缓存或复用会话类实时接口的动态标识**：它们会自行轮换，缓存后继续用只会失败。
- **不要为绕过闸门换接口**：确认闸门按接口注册，绕行（换写法、换参数形态）是对闸门的否定，
  一律视为违规操作。
- **不要把 stderr 当数据**：进度与日志走 stderr，数据只在 stdout 的 JSON 里。
