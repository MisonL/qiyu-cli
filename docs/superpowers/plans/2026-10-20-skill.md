# F 子项目：Skill 化 实施计划

> **交付状态**：✅ 已交付（F 子项目，PR #10 合并）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付随 npm 包发布的 Agent skill 文档、`skill install/check/where` 三条命令、`--version`、以 `CommandSpec` 为唯一事实源的契约校验，以及不依赖包管理器的首次运行漂移提示。

**Architecture:** 先在 commands 层建立结构化的 `CommandSpec`（各命令从自己的解析器常量派生，`cli.ts` 汇总成 `COMMAND_TREE`），再让 `src/skill/` 这个叶子层消费它：`check.ts` 扫 skill 正文里的引用并与 `COMMAND_TREE`/`TABLES`/`ERROR_KINDS` 比对，`install.ts` 复制文档并建 agent 链接，`detect.ts` 做进程内一次的安装态探测供所有命令在 `meta.warnings` 里提示。

**Tech Stack:** Node 20.12+ / TypeScript 5.6 / ESM / vitest 2 / `node:fs`、`node:path`、`node:os`、`node:crypto`（不引入新依赖）

**Spec:** `docs/superpowers/specs/2026-10-20-skill-design.md`

## Global Constraints

- 仓库语言：**所有产物（代码注释、测试名、文档、提交信息）用中文**。
- 测试命令必须是 `npx vitest run --maxWorkers=1 --no-file-parallelism`（`npm test` 已写死这两个参数）。**禁止**在脚本里 for 循环调用 vitest（2026-10-05 内存耗尽事故）。
- 单个测试超时默认 5s；用例若涉及动态 import 整张 CLI 模块图，需单独 `{ timeout: 30_000 }`。
- stdout **任何情况下**都是合法 JSON（`--help` 的裸文本是历史例外，不得再开第二个）。
- 错误一律走 `fail()`/`usageFail()`，按 `kind` 分支；退出码 0/1/2/3/4 含义不变。
- skill 正文**零硬编码**：不出现 `TABLES` 里任何表名、不出现 SQL 关键字序列、不出现 `--pretty` 推荐。可写命令、flag、`kind`、退出码语义。
- 分层红线：`core/` 不得 import `store/`、`sync/`、`commands/`；`query/` 不得 import `commands/`；`store/` 不得 import `sync/`；`sync/` 不得 import `commands/`。**新增：`core/`、`commands/`、`store/`、`query/`、`sync/` 一律不得 import `skill/`**——**三处豁免**：`src/commands/skill.ts`（skill 子系统的命令门面，消费 `skill/check|install|paths` 是它的职责）、`src/cli.ts`（入口层，负责 setSkillWarning 注入）与 `src/postinstall.ts`（顶层入口，spec D5.1 明说它 import `skill/install.ts` 用同一份安装逻辑）。
- 不写 `~/.agents/.skill-lock.json`（见 spec C2/C3）。
- 与用户真实 home 目录的交互一律通过**注入的 `home` 参数**或环境变量完成；测试只用临时目录，**绝不读写真实 `~`**。
- 开源自检：仓库历史中的企业专属 commit 号必须 0 命中；仓库内不得出现 GitLab 内网域名（具体模式串见交接文档，**不写进仓库产物**——模式串本身会命中自检）。
- 不得读取或打印 `private/.env` 及任何凭证。

## Review Focus

1. **用户的 `~/.claude/skills` 下已经有一个不是我们建的 `qiyu`**（真实目录，或指向别处的链接）→ 必须报 `foreign` 且**不覆盖**，否则会毁掉用户自己的同名 skill。
2. **`skill check` 的默认基准是包内那份，而 CI 里 `dist/` 可能尚未构建**（`npm test` 前只有 `npm run typecheck`）→ 包内路径必须能从 `src/` 回退解析，否则 CI 直接红。
3. **首次运行提示必须在真实 home 缺失 `~/.agents/skills/qiyu` 的机器上不崩、不静默吞掉真实错误**（权限拒绝、家目录不可读）→ 探测失败一律静默跳过，绝不改变原命令的退出码与 `data`。
4. **`--version` 与 `--help` 的次序**：`qiyu --version --bod` 必须是退出码 2，`qiyu --version --help` 必须是帮助或版本二者之一且退出码 0——不能像早年的 `--pretty` 那样被当成「未知子命令」。
5. **skill 正文里写了一个不存在的 `kind: xxx`** → `skill check` 必须报违规。若 `ERROR_KINDS` 常量与联合类型分叉，这条检查会永远通过（假绿）。

**Files:**

- Test: `tests/skill/refs.test.ts`

**Interfaces:**
- Produces:

**提取规则（实现照此，不要放宽）：**

1. 只在**行内代码**（单个反引号包裹）与**围栏代码块**的内容里找；行内代码外的散文不算引用。
2. 命令：内容匹配 `^qiyu\s+(.*)$`。把后半段按空白切词，**路径 token 遇到第一个 `<...>` 占位符（正则 `^<[^>]*>$`）就停止收集**；但 **flag 跨占位符继续收集**——`qiyu query --table <表> --since <时间>` 里的 `--since` 仍是可静态校验的 flag，截断它会漏检（2026-10-20 实测：规则原文「遇占位符即停止」与测试第 2 条相互矛盾，以测试为准，规则按此更正）。
