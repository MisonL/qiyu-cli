# 需要人工配置的 ID

有些 ID **无法通过开放 API 获得**，也没有「列表」接口可以枚举。缺它们时，正确的动作是
**停下来问人类**，而不是猜测、枚举或从别处硬推。

## 机器人编号（robotId）

机器人知识库的查询、机器人统计、机器人会话相关接口都以机器人编号为入参，但官方没有
「机器人列表」接口——枚举候选编号只会得到成片的「路由不存在」。

规则：

1. **缺失时问人类**。要「机器人编号清单」，不要自己编造、不要按数字区间试探、
   不要把会话里见过的编号当全量。
2. 人类把编号写进配置文件（两种写法都认，都在 `profiles.<name>` 之下）：
   - `profiles.<name>.store.options.knowledgeRobotIds`（正整数数组）—— **优先**；
   - `profiles.<name>.robots`（`{"1000001":"机器人A"}` 映射，键是编号、值是显示名）——
     `knowledgeRobotIds` 缺席时的兜底。

   ⚠️ **`knowledgeRobotIds` 在 `store` 块的 `options` 里面，比 `robots` 低两层** —— 两处写混
   （例如把 `knowledgeRobotIds` 直接放在 `profiles.<name>` 下）会被 CLI 以
   「配置文件未知键」拒绝（退出码 2）。转述给人类时请给**完整路径**，不要只说键名。

   `qiyu sync run` 在条目数据集为空（分类树没有可依据的编号来源）时会改用这些编号逐机器人
   拉取分类树；条目数据非空时以条目数据为准。写错（非正整数）会被 CLI 以用法错误拒绝并点名
   非法元素。`qiyu auth whoami` 的 `data.robots` 会如实列出配置里的映射（未校验有效性）。
3. 编号是否有效应以同步结果为准——同步后用 `qiyu db tables` 看知识库各数据集的行数是否非零。

### 两条补充发现路径（都只覆盖一部分，不替代手工配置）

- **从会话数据反推**：机器人会话的处理人编号与机器人编号存在固定的负数关系。会话数据
  同步完成后，可以按会话类型过滤出机器人会话、对处理人编号取不同值，得到一部分机器人编号。
  **它只能发现产生过会话的机器人**——新建的、没接待过的机器人不在其中。
- **从知识库条目反推**：知识库条目数据集自带机器人编号与名称字段。全量同步后按该字段
  分组即可得到一部分机器人编号。**它只能发现知识库非空的机器人**——空知识库的机器人不在其中。

两条路径互补，但**并集仍不完整**：既没有会话又没有知识库的机器人永远发现不了。
所以手工配置是基线，这两条只用来校验与补充；发现差异时报告人类，不要擅自改配置。

## 其他无列表接口的 ID

同类无法通过 API 列举、必须由人类提供的还有：

- **手动外呼任务编号**：没有「任务列表」接口。
- **外呼机器人任务编号**：同样没有列表接口。

涉及这两类任务时，先问人类要具体编号；拿 `qiyu sync tasks` 能列出的只是**同步任务**的编号，
它们是两回事，不要混用。

## 配置文件归人类

所有需要手工编辑的配置（存储位置、profile、机器人编号清单）都由人类维护在配置文件里。
Agent 的职责是：识别「缺配置」类错误 → 转述给人类 → 等人类配好 → 重新验证；
**不代写、不代改配置文件**（原因见 forbidden.md 第 1 条）。
