# 请求构建与 body 校验（B 子项目）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 `qiyu api call <id> --body <JSON>` 在**发出请求之前、本地**与注册表参数表比对（缺必填硬拒退出码 2、未知字段/类型不符给结构化 warnings），对已实测的字段改名做受控归一化，并新增 `qiyu api schema <id>` 子命令暴露参数表。

**Architecture:** 新增一个纯消费层：`src/core/registry/params.ts`（惰性读 + 缓存 + 结构校验 `loadParams`）、`src/core/validate.ts`（纯函数 `normalizeAliases` / `validateBody`）、`src/core/registry/validation-overrides.ts`（`validate.json` 的 fail-closed 加载）。`api.ts` 的 `callOne` 在 `byId`/`assertCallable` 之后、`assertConfirmed` 之前插入一个 B 块调用这三者；新增 `schema` 子命令与 `list`/`call` 同层。校验**先于**危险门禁（D5），且 `--no-validate` **绝不**削弱门禁。

**Tech Stack:** Node ≥ 20.10、TypeScript ESM（`.js` 后缀 import）、零运行时依赖、vitest 2.1.9（`vitest run --maxWorkers=1 --no-file-parallelism`）。

**Spec:** `docs/superpowers/specs/2026-10-10-请求构建与body校验-design.md`（v2.3，§十一 68 条修订记录、§九 35 条验收判据）——**实施前必读**，本计划每个任务都在其验收编号下有对应落点。

## Global Constraints

- **中文**：所有面向 Agent 的文本（`message`/`hint`/`field_notes`/README/CHANGELOG/测试标题与注释）一律中文；`kind`/`code` 用英文 snake_case。
- **零运行时依赖**：只用 `node:fs`/`node:url` + 静态 JSON import，**不新增任何 dependencies**。
- **退出码**：0 成功 / 1 业务（internal）/ 2 用法 / 3 网络 / 4 需 `--yes`。硬校验违规 → 2（普通 `Error`，**不挂 `kind`**）；params 文件缺失/畸形（命令执行期）→ 抛带 `kind:'internal'` 的 Error → 1。
- **测试命令**：`npx vitest run --maxWorkers=1 --no-file-parallelism <file>`。**禁止**任何 for/while 循环调用 vitest（2026-10-05 内存耗尽事故）。
- **提交**：每个任务末尾提交；commit message 末尾 `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`。
- **红线**：`--no-validate` **绝不**触碰 `assertConfirmed`（危险接口 + `--no-validate` + 合法/缺失 body + 无 `--yes` 仍返 4）。
- **`has_body_schema` 判据 = 合取式** `bodyKind === 'json' && body 参数数 > 0`，两个条件缺一不可。
- **口径统一**：校验相关文案里 CLI 输出键一律写 `response_shape`（下划线）；`params` 文件的 JSON 字段名才是 `responseShape`（驼峰）。
- **工作区**：本计划在 worktree 内执行，所有命令从 worktree 根运行。

## Review Focus

以下 5 类输入/条件，spec 隐含要求但容易被实现漏掉、且直接伤到使用者（Agent），按最可能出问题排序；每类在本计划里都有任务的测试钉住：

1. **硬拒消息误称「请求已发出」**——`--strict` 把 `unknown_field` 升级为硬拒时若复用软模板，会在退出码 2（无请求发出）的响应里宣称「请求已发出」。测试见 Task 6（验收 29 断言硬形态 message **不含**「已发出」）。
2. **软警告诱导重发危险写**——`unknown_field`/`type_mismatch`/`non_json_body` 的 message 若不含「已发出 + 不要重发」，一个「见 warning 就改输入重试」的 Agent 会**重复执行一次危险写**。测试见 Task 7（验收 5/9/28 断言三类 message 含「已发出」「不要重发」，`non_json_body` 且**不含**「未验证」）。
3. **`--no-validate` 削弱门禁**——若 `--no-validate` 跳过 `assertConfirmed`，危险接口将可无 `--yes` 发出。测试见 Task 6（验收 17：断言 fetch 未被调用且退出码 4）。
4. **别名改写只在测试里生效**——若 `call()` 收到的是 `JSON.parse` 原始 body 而非 `normalizeAliases` 改写后的，别名归一化在生产路径失效。测试见 Task 6（验收 7：mock 断言发给 `fetch` 的 body 含 `question`、不含 `name`）。
5. **`has_body_schema` 塌成单条件**——若实现成 `bodyKind === 'json'`（漏「>0」），`tag.all`（json、0 body）会被误判「有表」而对该接口的任意 body 静默通过与校验；反之若实现成 `>0`（漏 bodyKind），`kefu.add`（xml、14 body 参数）会被误标有表。测试见 Task 3/5（两个方向的等价变异体都钉：验收 8/27）。

// src/core/registry/params.ts
import { readFileSync } from 'node:fs'
import { fileURLToPath, pathToFileURL } from 'node:url'

export type BodyKind = 'json' | 'none' | 'form' | 'xml' | 'multipart' | 'text'
export interface ParamSpec {
  name: string
  in: 'query' | 'body' | 'path' | 'header'
  required: boolean
  type?: string
  description?: string
  example?: string
}
export interface ResponseShape { kind: string }
export interface ParamFile {
  params: ParamSpec[]
  bodyKind: BodyKind
  responseShape: ResponseShape
}

const BODY_KINDS = new Set<BodyKind>(['json', 'none', 'form', 'xml', 'multipart', 'text'])
const IN_KINDS = new Set(['query', 'body', 'path', 'header'])

/** 运行时校验 params 文件结构（in/required/type/bodyKind 枚举；同名跨 in 护栏），失败即抛。 */
export function validateParamsFile(id: string, raw: unknown): ParamFile {
  if (raw === null || typeof raw !== 'object' || Array.isArray(raw)) {
    throw new Error(`params/${id}.json 顶层必须是对象`)
  }
  const o = raw as Record<string, unknown>
  if (!Array.isArray(o.params)) throw new Error(`params/${id}.json 缺少 params 数组`)
  if (typeof o.bodyKind !== 'string' || !BODY_KINDS.has(o.bodyKind as BodyKind)) {
    throw new Error(`params/${id}.json 的 bodyKind 非法：${JSON.stringify(o.bodyKind)}`)
  }
  const rs = o.responseShape
  if (rs === null || typeof rs !== 'object' || typeof (rs as { kind?: unknown }).kind !== 'string') {
    throw new Error(`params/${id}.json 的 responseShape 必须是含 kind 字符串的对象`)
  }
  const seenBodyNames = new Set<string>()
  const seenQueryNames = new Set<string>()
  const params: ParamSpec[] = o.params.map((p, i) => {
    const e = p as Record<string, unknown>
    if (typeof e.name !== 'string' || !e.name) throw new Error(`params/${id}.json[${i}] 缺少 name`)
    if (typeof e.in !== 'string' || !IN_KINDS.has(e.in)) {
      throw new Error(`params/${id}.json[${i}] 的 in 非法：${JSON.stringify(e.in)}`)
    }
    if (typeof e.required !== 'boolean') {
      throw new Error(`params/${id}.json[${i}]（${e.name}）的 required 必须是布尔`)
    }
    if (e.in === 'body') {
      if (seenQueryNames.has(e.name as string)) {
        throw new Error(`params/${id}.json 的字段 ${e.name} 同时出现在 body 与 query —— (name,in) 身份歧义`)
      }
      seenBodyNames.add(e.name as string)
    } else if (e.in === 'query') {
      if (seenBodyNames.has(e.name as string)) {
        throw new Error(`params/${id}.json 的字段 ${e.name} 同时出现在 body 与 query —— (name,in) 身份歧义`)
      }
      seenQueryNames.add(e.name as string)
    }
    return e as unknown as ParamSpec
  })
  return { params, bodyKind: o.bodyKind as BodyKind, responseShape: rs as ResponseShape }
}

let injectedRoot: string | undefined
/** 测试专用：设置 params 根目录。生产不调用（injectedRoot 恒 undefined，用 import.meta.url 定位）。 */
export function setParamsRoot(dir: string | undefined): void { injectedRoot = dir }

// ⚠️ 同进程内 root 一经首次读取即并入缓存（键为 `${root}\0${id}`）。同一路径内容被改写后
// 要靠新模块图才能重读——但改 root 本身不需要 reset（不同 root 是不同缓存键）。
const cache = new Map<string, ParamFile>()

/** 惰性读 + 缓存；缺文件/畸形 JSON/结构非法 → 抛 kind:'internal'。 */
export function loadParams(id: string, root: string | undefined = injectedRoot): ParamFile {
  const base = root ?? fileURLToPath(new URL('.', import.meta.url))
  const key = `${base}\0${id}`
  const hit = cache.get(key)
  if (hit) return hit
  let raw: unknown
  try {
    raw = JSON.parse(readFileSync(fileURLToPath(new URL(`./params/${id}.json`, pathToFileURL(base + '/'))), 'utf8'))
  } catch (e) {
    throw Object.assign(
      new Error(`读取 params/${id}.json 失败：${e instanceof Error ? e.message : String(e)}`),
      { code: 'internal', kind: 'internal', retryable: false,
        message: `params/${id}.json 缺失或损坏 —— 这是 CLI 的打包/注册表缺陷，不是你的请求或服务端的问题`,
        hint: '重装或报告此问题；params 文件缺失或损坏' },
    )
  }
  let file: ParamFile
  try {
    file = validateParamsFile(id, raw)
  } catch (e) {
    throw Object.assign(
      new Error(`params/${id}.json 结构非法：${e instanceof Error ? e.message : String(e)}`),
      { code: 'internal', kind: 'internal', retryable: false,
        message: `params/${id}.json 结构非法 —— 这是 CLI 的打包/注册表缺陷，不是你的请求或服务端的问题`,
        hint: '重装或报告此问题；params 文件缺失或损坏' },
    )
  }
  cache.set(key, file)
  return file
}

// src/core/registry/validation-overrides.ts
import raw from './validate.json' with { type: 'json' }
import { allEndpoints, type EndpointSpec } from './index.js'
import { loadParams, type ParamFile } from './params.js'

export interface ValidationOverride {
  note?: string
  relaxRequired?: string[]
  oneOf?: { anyOf: string[]; message: string }[]
  aliases?: Record<string, string>
}

/** 纯函数：fail-closed 校验（§五 加载规则），坏数据抛普通 Error（模块初始化期由入口兜底为裸崩）。 */
export function validateOverrides(
  rawIn: unknown,
  specs: readonly EndpointSpec[],
  paramsFor: (id: string) => ParamFile,
): Record<string, ValidationOverride> {
  if (rawIn === null || typeof rawIn !== 'object' || Array.isArray(rawIn)) {
    throw new Error('validate.json 顶层必须是对象')
  }
  const ids = new Set(specs.map((s) => s.id))
  const out: Record<string, ValidationOverride> = {}
  for (const [id, v] of Object.entries(rawIn as Record<string, unknown>)) {
    if (!ids.has(id)) throw new Error(`validate.json 的键 ${id} 不是注册表里的接口 id`)
    const o = v as Record<string, unknown>
    const file = paramsFor(id)
    const bodyNames = new Set(file.params.filter((p) => p.in === 'body').map((p) => p.name))
    const requiredBody = new Set(file.params.filter((p) => p.in === 'body' && p.required).map((p) => p.name))
    const ov: ValidationOverride = {}
    if (o.note !== undefined) {
      if (typeof o.note !== 'string') throw new Error(`validate.json[${id}].note 必须是字符串`)
      ov.note = o.note
    }
    if (o.relaxRequired !== undefined) {
      if (!Array.isArray(o.relaxRequired) || !o.relaxRequired.every((x) => typeof x === 'string')) {
        throw new Error(`validate.json[${id}].relaxRequired 必须是字符串数组`)
      }
      for (const f of o.relaxRequired as string[]) {
        if (!bodyNames.has(f)) throw new Error(`validate.json[${id}].relaxRequired 引用了非 body 字段 ${f}`)
        if (!requiredBody.has(f)) throw new Error(`validate.json[${id}].relaxRequired 引用了非必填字段 ${f}（无效果死配置）`)
      }
      ov.relaxRequired = o.relaxRequired as string[]
    }
    if (o.oneOf !== undefined) {
      if (!Array.isArray(o.oneOf)) throw new Error(`validate.json[${id}].oneOf 必须是数组`)
      ov.oneOf = (o.oneOf as unknown[]).map((g, gi) => {
        const gg = g as { anyOf?: unknown; message?: unknown }
        if (!Array.isArray(gg.anyOf) || gg.anyOf.length < 2 || !gg.anyOf.every((x) => typeof x === 'string')) {
          throw new Error(`validate.json[${id}].oneOf[${gi}].anyOf 必须是 ≥2 的字符串数组`)
        }
        for (const f of gg.anyOf as string[]) {
          if (!bodyNames.has(f)) throw new Error(`validate.json[${id}].oneOf[${gi}].anyOf 引用了非 body 字段 ${f}`)
        }
        if (typeof gg.message !== 'string') throw new Error(`validate.json[${id}].oneOf[${gi}].message 必须是字符串`)
        return { anyOf: gg.anyOf as string[], message: gg.message }
      })
    }
    if (o.aliases !== undefined) {
      if (o.aliases === null || typeof o.aliases !== 'object' || Array.isArray(o.aliases)) {
        throw new Error(`validate.json[${id}].aliases 必须是对象`)
      }
      for (const [src, dst] of Object.entries(o.aliases as Record<string, unknown>)) {
        if (typeof dst !== 'string') throw new Error(`validate.json[${id}].aliases 的目标键必须是字符串`)
        if (!bodyNames.has(dst)) throw new Error(`validate.json[${id}].aliases 的目标键 ${dst} 不是 body 字段`)
        if (bodyNames.has(src)) throw new Error(`validate.json[${id}].aliases 的源键 ${src} 本身就是 body 字段（不该被别名覆盖）`)
      }
      ov.aliases = o.aliases as Record<string, string>
    }
    out[id] = ov
  }
  return out
}

/** 生产入口：静态 import → validateOverrides（与 loadSpecs 同款两段式）。 */
export function loadValidationOverrides(): Record<string, ValidationOverride> {
  return validateOverrides(raw, allEndpoints(), loadParams)
}

// src/core/validate.ts
import type { ParamFile } from './registry/params.js'
import type { ValidationOverride } from './registry/validation-overrides.js'
import type { EndpointSpec } from './registry/index.js'

export interface Violation { kind: string; field?: string; message: string }
export interface ValidateResult { hard: Violation[]; soft: Violation[] }

const isPlainObject = (v: unknown): v is Record<string, unknown> =>
  v !== null && typeof v === 'object' && !Array.isArray(v)

/** 归一化别名（D8）：返回改写后的 body 与 alias_normalized 警告；源/目标键冲突 → 抛（硬）。 */
export function normalizeAliases(
  file: ParamFile, body: unknown, ov: ValidationOverride | undefined,
): { body: unknown; warnings: Violation[] } {
  // ⚠️ 非普通对象原样返回：别名扫描只对普通对象做，绝不在 undefined 上调 Object.keys/展开。
  if (!ov?.aliases || !isPlainObject(body)) return { body, warnings: [] }
  const aliases = ov.aliases
  const srcPresent = Object.keys(aliases).filter((s) => Object.hasOwn(body, s))
  if (srcPresent.length === 0) return { body, warnings: [] }
  for (const s of srcPresent) {
    if (Object.hasOwn(body, aliases[s])) {
      throw new Error(`body 同时含别名源键 ${s} 与目标键 ${aliases[s]} —— 只能传其一`)
    }
  }
  // 按 body 键出现顺序输出 warning
  const warnings: Violation[] = []
  const rewritten: Record<string, unknown> = {}
  for (const [k, v] of Object.entries(body)) {
    if (Object.hasOwn(aliases, k)) {
      const dst = aliases[k]
      rewritten[dst] = v
      warnings.push({ kind: 'alias_normalized', field: k,
        message: `${k} 已按本接口约定改写为 ${dst} 发送；请求正常，无需重试` })
    } else {
      rewritten[k] = v
    }
  }
  return { body: rewritten, warnings }
}

const BODY_TYPE_MAP: Record<string, (v: unknown) => boolean> = {
  string: (v) => typeof v === 'string',
  integer: (v) => typeof v === 'number',
  number: (v) => typeof v === 'number',
  boolean: (v) => typeof v === 'boolean',
  array: (v) => Array.isArray(v),
  object: (v) => v !== null && typeof v === 'object' && !Array.isArray(v),
}
/** 渲染实际类型（固定词汇，不用 typeof —— typeof null/[] 都是 object）。 */
function renderActual(v: unknown): string {
  if (v === null) return 'null'
  if (Array.isArray(v)) return '数组'
  return typeof v
}

/** 纯函数：顶层形状契约 + 硬/软规则；不碰 I/O。 */
export function validateBody(
  spec: EndpointSpec, file: ParamFile, body: unknown,
  ov: ValidationOverride | undefined, mode: { strict: boolean },
): ValidateResult {
  // hasBodySchema 判据 = 合取式（§三/§八.6）：bodyKind==='json' 且 body 参数数 > 0。
  const bodyParams = effectiveBodyParamsLocal(file, ov)
  const hasBodySchema = file.bodyKind === 'json' && bodyParams.length > 0
  // bodyKind !== 'json' 的接口根本不进形状表：只可能出 non_json_body（软）。
  if (file.bodyKind !== 'json') {
    if (body === undefined) return { hard: [], soft: [] }
    return { hard: [], soft: [{ kind: 'non_json_body',
      message: `本接口 body_kind 是 ${file.bodyKind}，你的 --body 已按原样字面量发送、未经字段校验；本 CLI 不构造非 JSON 的 body 编码。该字面量已随请求发出，不要因「未验证」而重发` }] }
  }
  if (!hasBodySchema) return { hard: [], soft: [] }  // json 但 0 body 表：形状也不判

  const hard: Violation[] = []
  // 非对象 body + 有表 → 硬拒
  if (body === undefined) {
    const missing = bodyParams.filter((p) => p.required)
    if (missing.length > 0) {
      return { hard: [{ kind: 'missing_required', field: missing[0].name,
        message: `未传 --body，但该接口需要 JSON 对象 body（缺必填字段：${missing.map((p) => p.name).join('、')}）。用 qiyu api schema ${spec.id} 查看完整参数表` }], soft: [] }
    }
    return { hard: [], soft: [] }
  }
  if (!isPlainObject(body)) {
    return { hard: [{ kind: 'non_object_body',
      message: `该接口需要 JSON 对象 body，实际是 ${body === null ? 'null' : Array.isArray(body) ? '数组' : '标量'}。用 qiyu api schema ${spec.id} 查看参数表` }], soft: [] }
  }

  const bodyNames = new Set(bodyParams.map((p) => p.name))
  const aliasSrc = new Set(Object.keys(ov?.aliases ?? {}))
  const soft: Violation[] = []
  // 硬：逐字段缺必填（params 表顺序）
  for (const p of bodyParams) {
    if (p.required && (!Object.hasOwn(body, p.name) || body[p.name] === undefined)) {
      hard.push({ kind: 'missing_required', field: p.name,
        message: `缺少必填字段 ${p.name}（body 里没有该键）。用 qiyu api schema ${spec.id} 查看完整参数表` })
    }
  }
  // 硬：one-of 组（组内任一存在即满足；全缺 → 用 override message），排在 per-field 之后
  for (const g of ov?.oneOf ?? []) {
    if (!g.anyOf.some((f) => Object.hasOwn(body, f) && body[f] !== undefined)) {
      hard.push({ kind: 'one_of_missing', message: g.message })
    }
  }
  if (hard.length > 0) return { hard, soft: [] }  // 硬违规短路

  // 软：unknown_field（body 键序）、type_mismatch（params 表序）
  for (const k of Object.keys(body)) {
    if (!bodyNames.has(k) && !aliasSrc.has(k)) {
      soft.push({ kind: 'unknown_field', field: k,
        message: `字段 ${k} 不在本接口的文档参数表中，服务端可能忽略它；但本次请求已经发出（退出码 0）——不要重发（重发 = 再执行一次接口，写接口会重复写入）` })
    }
  }
  for (const p of bodyParams) {
    if (p.type && Object.hasOwn(body, p.name) && body[p.name] !== undefined) {
      const check = BODY_TYPE_MAP[p.type]
      if (check && !check(body[p.name])) {
        soft.push({ kind: 'type_mismatch', field: p.name,
          message: `字段 ${p.name} 声明类型 ${p.type}，实际是 ${renderActual(body[p.name])}。本值已随请求发出（退出码 0），不要重发` })
      }
    }
  }
  // strict 升级：unknown_field / type_mismatch 从软转硬（硬形态 message 不得含「已发出」）
  if (mode.strict) {
    const upgraded = soft.filter((w) => w.kind === 'unknown_field' || w.kind === 'type_mismatch')
    if (upgraded.length > 0) {
      const hardMsgs: Violation[] = upgraded.map((w) => ({ kind: w.kind, field: w.field,
        message: w.kind === 'unknown_field'
          ? `本地参数表未收录字段 ${w.field}，未发出请求，请修正后重试（这是本地参数表闭集一致性检查，不是对服务端行为的保证 —— 若确认该字段合法，请改用默认模式或报告缺失的注册表项，不要删字段重试）`
          : `字段 ${w.field} 类型不符，未发出请求，请修正后重试` }))
      return { hard: hardMsgs, soft: [] }
    }
  }
  return { hard: [], soft }
}

const SCHEMA_KNOWN = new Set(['--pretty', '--help', '-h'])
const SCHEMA_USAGE = `用法：qiyu api schema <接口id> [--pretty]\n\n  查看某接口的请求参数表（params）与响应形状（response_shape）。\n\n--pretty  尚未实现（无参数替代它）。当前只输出紧凑 JSON。\n`

async function schema(argv: string[]): Promise<number> {
  const unknown = argv.filter((a) => a.startsWith('-') && !SCHEMA_KNOWN.has(a))
  if (unknown.length > 0) return usageFail(`未知参数：${describeArgs(unknown)}。可用：--pretty`)
  const positional = argv.filter((a) => !a.startsWith('-'))
  const help = argv.includes('--help') || argv.includes('-h')
  // 3a/3b：help 优先于「缺 id」与「位置参数 > 1」，但自身检查位置参数
  if (help) {
    if (positional.length > 0) return usageFail(`未知参数：${describeArgs(positional)}。--help 不接受额外参数`)
    process.stdout.write(SCHEMA_USAGE)
    return EXIT.OK
  }
  if (positional.length > 1) return usageFail(`未知参数：${describeArgs(positional.slice(1))}。api schema 只接受一个接口 id`)
  if (argv.includes('--pretty')) return usageFail('--pretty 尚未实现（无参数替代它）。当前只输出紧凑 JSON。')
  if (positional.length === 0) return usageFail('用法：qiyu api schema <接口id>')
  const id = positional[0]
  try {
    const spec = byId(id)
    const file = loadParams(spec.id)
    const ov = loadValidationOverrides()[spec.id]
    const bodyParams = effectiveBodyParams(file, ov)
    const hasBodySchema = file.bodyKind === 'json' && bodyParams.length > 0
    const AUTH = new Set(['appKey', 'time', 'checksum'])
    const params: SchemaParam[] = file.params.map((p) =>
      p.in === 'query' && AUTH.has(p.name) ? { ...p, auto: true as const } : { ...p })
    const data: Record<string, unknown> = {
      id: spec.id, title: spec.title, method: spec.method, path: spec.path,
      callable: spec.callable, dangerous: spec.dangerous,
      body_kind: file.bodyKind, has_body_schema: hasBodySchema,
      params, response_shape: file.responseShape,
      ...(ov?.oneOf ? { one_of: ov.oneOf } : {}),
    }
    return ok(data, {
      endpoint: spec.id,
      ...(spec.note ? { note: spec.note } : {}),
      field_notes: {
        has_body_schema: 'true = 本接口有可比对的 body 参数表（body_kind 为 json 且 body 参数数 > 0）；不代表本次请求已校验，也不代表其余 bodyKind。本次校验结果见 api call 的 meta.warnings',
        body_kind: '只有 json 会被 api call 比对字段，其余（none/xml/multipart/text/form）原样透传不校验',
        auto: 'true = CLI 自填的鉴权 query 参数（appKey/time/checksum），调用方不要也不能通过 --body 传',
        dangerous: 'true = 危险操作，调用时需 --yes，否则退出码 4。必须由人类确认，不要自动追加 --yes',
        callable: 'false = 结构上不可主动调用（如 inbound 推送）；Agent 只能查、不能调',
        path: 'null = 路径未收录（数据缺口）；"/" = 入站占位符。两者都不可据此拼 URL',
        response_shape: '仅供参照，不做校验',
        one_of: 'one_of 数组每项是一组「组内任一存在即可满足」的字段，全缺会被拒绝（退出码 2）；组内字段的 required 已因此降为 false —— false 是「二选一」的意思，不是「两个都可省」',
      },
    })
  } catch (e) {
    const err = e as Partial<{ code: string; kind: string; retryable: boolean; message: string; hint: string }>
    if (err.kind && err.kind !== 'usage') {
      return fail({ code: err.code ?? 'unknown', kind: err.kind, retryable: err.retryable ?? false, message: err.message ?? String(e), hint: err.hint })
    }
    const message = e instanceof Error ? e.message : String(e)
    process.stderr.write(message.endsWith('\n') ? message : message + '\n')
    return fail({ code: 'usage', kind: 'usage', retryable: false, message: message.replace(/\n+$/, '') })
  }
}
