## 2. P0 · Windows 凭证权限：证据链与裁决

### 2.1 三层失效（【已验证】，静态 + 真机）
- **写入不收紧**：`writeConfigFile`（`src/core/config.ts` 的 `writeConfigFile`）在 win32 上 `mkdir mode:0o700`「Not supported on Windows」、`writeFileSync{mode:0o600}` + `chmodSync(0o600)` 只映射「只读属性」——**NTFS DACL 零改变**。
- **门禁不拦截**：`checkPermissions:371` 首行 `if (process.platform === 'win32') return {ok:true}`，「含凭证过宽即拒绝」在 Windows 上整条蒸发（连警告都没有）。
- **自检恒 ok**：`auth login` 写后自检调 `checkPermissions`（`auth.ts` 的「权限自检」段），win32 短路使它在 Windows 上 **恒返回 ok**——`configured:true` 里的「权限已复核」这层含义在 Windows 上没有发生；而同一函数上方的注释把 「凭证已落盘且可被他人读却报成功」定义为假成功，win32 路径恰好落进自己定义的形态。 · **边界澄清（Codex P1-4）**：自检的 `catch { }` 吞错是**另一件事**——它对全平台一致、注释写明是有意的 （「自检失败不影响已写入这一事实；下一次任何命令都会再查一次」），不是 win32 特有。 spec 此前把两者压成 「自检恒真」一句，读起来像 catch 也是 win32 分支——修法里两者要分开对待。- **影响面（按调用链列，Codex P1-4 要求）**：`writeConfigFile` 的直接写入方只有 `auth login`；`checkPermissions` 直接调用点三处 （login 自检、`loadConfigChecked`、`store/config.ts resolveStoreConfig`），传递覆盖 `auth whoami`、`api call`、 `sync run/status/verify/install/uninstall`、`store/db/query/stats` 全族与限流 fallback 探测；`api list`/`api schema`/ `skill *`/`--version` 不读配置，不在其内。

### 2.2 真机决定性证据（M1 + 我亲自复核 T-8/T-7a）
- **M1（有效证据）**：Windows 上 0600/0644/0666 四种造法的文件，`icacls` 输出**逐字节相同**、`statSync().mode` 全部回读 `666`；把 config.json 显式 `/grant` 给 `Everyone:(R)` + `BUILTIN\Users:(R)`（**RC=0、ACE 在、含凭证**）后 `auth whoami` **RC=0** 照常返回 `configured:true`，不报 `config_insecure`；`icacls /reset` 回纯继承后仍 RC=0。
- **T-8**：git 历史证明两个函数自 `5650cfa`(G1/v0.2.0) 引入、v0.2.1→v0.2.3 函数体哈希相同 ——「非 0.2.2 回归」 **这一半是源码历史可复核的**；另 一 半 「三版产物在 Windows 上 ACL 逐字节相同」只是**本机样本观察** （原始输出见 `private/evidence/2026-11-22-windows-acl/raw-outputs.md`，gitignored），不推广为普遍结论。该缺陷是 **G1（PR #13，v0.2.0 起）的存量**，0.2.2 在权限域反而往诚实方向走（新增 ACL 拒绝的平台分流）。用户「0.2.2 起」是观测时点，不是回归点。
- **T-7a（精确归因）**：M1 环境中那条**测试机特有的某沙箱服务组**的 `(I)(M,DC)` ACE 来自 `%TEMP%` 目录本身（新建任意文件都继承），**不是 qiyu 写入的、也不是全体登录用户可读**。真实暴露面按「NTFS 默认 ACL 可能授予广域主体 + CLI 不检查也不告警」陈述，**不夸大**成「所有登录用户可读」。
- **T-8 附加**：Windows上 `os.homedir()` 只认 `USERPROFILE`（HOME 完全忽略）；OpenSSH 会话里 `USERPROFILE` 指向 Temp——路径契约在 Windows 上比预想复杂。
- **我方探针诚实记录**：我自己跑的一轮「放宽 Everyone 后 whoami rc=0」是**无效探针**（凭证从 env 读、`grant` 静默失败、ACE 没落上）；「门禁不拦」只以 M1 那份有效证据为准。

### 2.3 Linux 正确基线（M2，全实测）
文件 600 / 目录 700 且与 umask 077/022/**000** 无关；644 → whoami rc=1 `config_insecure` + `chmod 600` hint；目录 757/777 → 拦、755 不拦（判据 `&0o022`）；把 login 产物复制成 644 后 `nobody` 真能读出 secret（泄露面真实）；644 下 `login` 静默自愈为 600、777 目录下 login 报「已写入但自检不合格」；符号链接**只写侧拒绝、读侧跟随**。

### 2.4 修法（两阶段，A 未实测前不写 README 承诺）
1. **方案 B（立即，低成本诚实）**：README(:122、:176-193)、design(:169/:185)、`errors.md` ①档、`auth login` help/field_notes、`writeConfigFile` 注释统一收窄为「POSIX 域承诺；Windows 上 mode 不落 ACL、CLI 不检查也不告警，暴露面由 NTFS 默认 ACL 决定，需人工 `icacls`」；把无条件 `statSync().mode & 0o777` 断言逐处平台化（清点：`tests/core/config.test.ts:283,284,295,302` + `tests/commands/auth.test.ts:237,238` 共 6 处，另有两文件各自的 `writeCfg(mode=0o600)` 夹具默认值）。
2. **方案 A（以真机为闸）**：写入侧 win32 显式 `icacls /inheritance:r /grant:r "*<当前用户 SID>:(R,W)"`——数值 SID **必须带 `*` 前缀**（`icacls` 语法要求，实测同此），且按 **SID** 不按本地化 trustee 名（中文 Windows 的 `icacls` 输出是本地化的——同「按错误文本分流」红线）；**写序与 ACL 落点（CodeRabbit #82 major 的追问）**：`writeConfigFile` 是「写 tmp → `renameSync` 换入」。 `rename` 是**换入对象**——换入后目标的 ACL 取 **源文件（tmp）**的，**目标旧 DACL 不保留**（**实测 T-9b**：对已显式放宽过 `Everyone:(R)` 的目标做 `mv` 覆盖，换入后 ACL 变成 tmp 的目录继承态、旧 `Everyone` 授权消失）。所以"保留旧 DACL 再写凭证"这条泄露路径在 **当前 tmp→rename 形态下不成立**。**写序必须三步分开（Codex 对 PR #82 的 P1-1——比 rename 语义更早的一处泄露）**：win32 上 `writeFileSync(tmp, secret)` 会按父目录继承的 DACL 创建 tmp，**secret 在被收紧之前就已经躺在 tmp 里**（当前代码先写后 `chmod`，而 `chmod` 不落 DACL → 整个写入窗口 tmp 都是继承可读的）。正确顺序：① **建空 tmp**（不写 secret）；② 对它 `icacls /inheritance:r /grant:r "*<SID>:(R,W)"` 收紧，并**读回确认收紧成功**；③ 收紧到位后才 `writeFileSync` secret；④ `renameSync` 换入。**任一步失败就删除 tmp 且不换入**（不留一个收紧失败、含 secret 的文件在继承目录里）。换入后目标的 ACL 继承自这个已收紧的 tmp——「换入会把收紧带过去」只有在「先收紧再写入」的前提下才成立，否则只是把带 secret 的宽松 tmp 换进目标位置。**若**将来改成对现有文件 **原地改写**（不走换入），则 `/inheritance:r` 只断继承、`/grant:r <自己>` 不删**他人已显式授予**的 ACE——旧的 `Everyone`会存活，那种形态必须额外 `/remove` 广域主体。**收尾一律对最终路径复核一次 ACL **（见下探测），别假设写序正确。`checkPermissions` win32 分支改**真探测 ACL**——探测不能只看「当前用户可不可达」，必须**枚举现有 ACE 并按「最小允许名单」判**：只有当前用户 SID（以及 `*S-1-5-18` SYSTEM、`*S-1-5-32-544` BUILTIN\Administrators 这两个设计上本就等价全权的内置主体）可以持有允许 ACE，**出现任何其他主体的允许 ACE 即判 `ok:false`，不论它是不是广域主体**。**不得写成广域主体黑名单**（Everyone/Users/Authenticated Users 枚举）——黑名单天然漏一族：`icacls /grant:r <某个具名用户>:(R)` 的显式授权不在名单里，却同样让那个账户读到 `appSecret`，探测却报 `checked:true, ok:true`（CodeRabbit round 74 指出的正是这一形态，与本 spec「凭证可被他人读却报成功」的定义同类）；那个具名用户即使在别处有 deny ACE 也按「先判 allow 名单」处理——宁可误报要求人工 `icacls` 清理，也不放过。**「空名单」不等于「已保护」——必须先把 DACL 本身的存在性与空态判掉（CodeRabbit round 75）**：Windows 的 **null DACL**（安全描述符里 `DACL` 指针为空）表示「无访问控制」——**所有人都拿到完全访问**，它枚举出来的 ACE 列表同样是空的，光按「没有名单外主体的允许 ACE」判会把这种最危险的形态判成 `checked:true, ok:true`。判据顺序固定为三步：① **DACL 存在**（null DACL → 直接 `ok:false`）；② **DACL 非空**（空 DACL 是「显式拒绝所有人」：文件连当前用户都读不了，不是本 CLI 写序可能产出的形态，如实判 `ok:false` 并提示重建 ACL，而不是当「收紧得好」放行）；③ 再做允许名单判断。候选机制是 PowerShell `Get-Acl` 的 SDDL 形态（null DACL 为 `D:NO_ACCESS_CONTROL`、空 DACL 为 `D:`，两者枚举 ACE 都是空列表，**只有 SDDL 能区分**）——该机制**尚未真机实测**，实施前必须在 Windows 真机上各造一个（`icacls` 能造空 DACL；null DACL 需 PowerShell/.NET 设置 `SetSecurityDescriptorSddlForm('D:NO_ACCESS_CONTROL')`）并读回确认，实测定稿前不把这条写成「已验」。判据取 **SID + 访问掩码**，不解析 `icacls` 输出里的本地化权限文本（`(F)/(M)/(RX)/(R)` 一类 token 的中文输出形态**未经实测**，不拿它做判据；取 SID/掩码的候选机制——PowerShell `Get-Acl` 的 `FileSystemRights` 枚举值 + `Translate([SecurityIdentifier])`——需真机验证后再定稿）；按 **SID** 判不按本地化名，规避中文 Windows `icacls` 输出本地化——同「按文本分流」红线；收紧用的是**重建整份 DACL**（断继承 + 删他人显式 ACE + 仅授当前用户），`/grant:r <自己>` 单用**不会删别人的显式授权**，残留即泄露；返回三态 `{ok:true, checked:true|false}`，三个调用点（`auth login` 的「权限自检」段、`core/config.ts` 的 `loadConfigChecked`、`store/config.ts` 的 `resolveStoreConfig`）把「判定不了」如实透出；不得复用 `mode & 0o077` 判据（Windows 正常文件回读 666，会把所有人误拒）。非 NTFS / icacls 不可用 → 「判定不了」，不冒认 ok。
3. **同构面裁决**：`store init` 创建的 DuckDB 库文件（含业务数据）同样无权限收紧——要明确「一并收口」还是「明确非目标并声明」，不留下沉默缺口。

### 2.5 回归防线
CI 仅 `ubuntu-latest`（`.github/workflows/ci.yml:18-25`），**无测试钉住 win32 短路本身**。建议最小 windows-latest job（跑不依赖 POSIX 的 auth/config/hint 方言子集）+ 静态守卫钉「win32 短路不得无覆盖静默存在」。ACL 夹具清单（0.2.4 实施时必须齐全，每条都要真机跑）：
1. 纯继承（默认新建）→ 判 `ok:false`（继承 ACE 未收紧）；
2. `/grant Everyone:(R)` → `ok:false`；
3. **`/grant *<另一个具名用户 SID>:(R)`、且无对应 deny ACE** → 必须 `ok:false`——这是防止探测判据退化回「广域黑名单」的最小反例（CodeRabbit round 74）；写成黑名单的实现只有这条会红；
4. 按修法收紧后（`/inheritance:r` + 仅授当前用户）→ `ok:true, checked:true`；
5. icacls/PowerShell 不可用或非 NTFS → `checked:false`，不得冒认 ok；
6. **null DACL**（`D:NO_ACCESS_CONTROL`，等于所有人完全访问）→ 必须 `ok:false`——ACE 列表为空，
   只数 ACE 的实现会把它判成「干净」，这是判据最危险的一种假绿（CodeRabbit round 75）；
7. **空 DACL**（`D:`，显式拒绝所有人的访问）→ 同样 `ok:false` 并提示重建 ACL，不得当成「收紧得好」；
8. 正常受限 DACL（夹具 4 的那份）→ 仍须 `ok:true, checked:true`，证明①判空态没有把好形态一起拒掉。
