## Review Focus（最可能咬人的输入类，各配钉死用例）

1. **沙箱层序**：`TimeZone`/`memory_limit` 必须在 `lock_configuration=true` 之前；lock 后改配置必须报错（Task 3）。
2. **`runAndReadUntil` 不精确限行**：按 chunk 倍数多读；截断判定用「返回行数 > limit」，不是「=== limit+1」（Task 3/8）。
3. **多语句闸门**：`count===1` 是必需闸门；`prepare(0)` 只执行第一条（Task 3）。
4. **iso-day 的 `--since` 向下取整**：9/15 12:00 的 since 必须包含 `stat_date = 9/14T16:00Z` 的行（Task 9）。
5. **脱敏的两种通道**：`--table` 精确、`--sql` 列名级 + 值级兜底；`payload` 在 `--sql` 通道**不做列名级**（否则报表 payload 被误杀），靠 JSON 值级检测（Task 4/8）。
6. **声明与实况不一致**：`TABLES` vs `information_schema` 必须 warning，不静默（Task 6/7）。

实现要点（逐条对应 spec §5.2/§5.3）：
1. `const mod = await (deps?.importer ?? (() => import('@duckdb/node-api')))()`；`ERR_MODULE_NOT_FOUND` → 复用 `isModuleNotFound`（从 `store/duckdb.ts` 导入；若未导出则导出它）→ 错误带 `kind: 'store_not_initialized'` + 安装指引。
2. ro 打开复用 `retryWithBackoff` / `isLockError`（`store/retry.js`），超限 → `kind: 'store_locked'`（消息与 duckdb.ts 同款）。
3. SET 顺序**严格**：`TimeZone` → `memory_limit='1GB'` → `enable_external_access=false` → `lock_configuration=true`；每条经 `conn.run(...)`。
4. 自检 `SELECT current_setting('enable_external_access') AS ea, current_setting('lock_configuration') AS lc`；非 `false/true` → close + `kind:'internal'` 错误「只读沙箱自检失败」。
5. `run(sql, { params = [], limit = 1000, timeoutMs = 30000 })`：
   - `limit` 必须是 1–10000 的整数，否则抛 `kind:'usage'`；
   - `extractStatements(sql)`：抛异常或 `count === 0` → `usage`「SQL 为空或无有效语句」；`count > 1` → `usage` + `code:'sandbox_blocked'`「一次只接受一条语句（检测到 N 条）」；
   - `prepare(0)`：抛异常 → 交给错误映射（Task 5 的函数在 sandbox 内先粗分类，见下）；`p.parameterCount !== params.length` → `usage`「SQL 含 N 个参数占位符，--sql 不接受参数」；
   - `statementType`：从 `mod.StatementType` 取 `SELECT`/`EXPLAIN`（常量回退 1/4，注释注明实测值）；非二者 → `usage` + `code:'sandbox_blocked'`，消息含类型名（映射表：2 INSERT / 7 CREATE / 11 COPY / 16 EXPORT / 17 PRAGMA / 19 CALL / 20 SET / 21 INSTALL / 25 ATTACH，其余「类型 N」）；
   - 执行：`const timer = timeoutMs > 0 ? setTimeout(() => conn.interrupt(), timeoutMs) : null`；`const reader = await p.runAndReadUntil(limit + 1)`；`finally clearTimeout(timer)`；捕获消息含 `INTERRUPT` → `kind:'query_timeout'`；
   - `const rows = reader.getRowObjectsJson()`；`truncated = rows.length > limit`；`rows = rows.slice(0, limit)`；`columns = rows.length ? Object.keys(rows[0]) : reader.columnNames()`。
6. `close()`：`conn.closeSync?.()` → `inst.closeSync?.()`（与 `store/duckdb.ts:305` 同序），幂等。
7. 所有抛出错误带 `kind`（`usage` / `store_locked` / `store_not_initialized` / `internal` / `query_timeout`）与可选 `code`、`hint`，供命令层 `thrownToExit` 同族映射。
8. `src/core/errors.ts` 的 `ErrorKind` 联合类型追加 `'query_timeout'`（注释：只读查询超时，退出码 1；`exitCodeFor` 不设分支，落 default）。

```ts
export type MaskRule = 'phone' | 'email' | 'ip' | 'full'
export function maskValue(v: unknown, rule: MaskRule): unknown
export function ruleForColumn(name: string): MaskRule   // userPhone/crmUserPhone/userMobile→phone；*Email→email；fromIp→ip；其余 full
export interface MaskOutcome { rows: Record<string, unknown>[]; maskedColumns: string[]; warnings: string[] }
export function maskQueryRows(input: {
  rows: Record<string, unknown>[]; columns: string[]
  mode: { kind: 'table'; table: TableDef } | { kind: 'sql'; sql: string; tables: TableDef[] }
  noMask?: boolean
}): MaskOutcome
```

```sql
WITH kv AS (
  SELECT j.k AS k,
         json_extract(t.payload, '$."' || j.k || '"') AS raw
  FROM "表" t, unnest(json_keys(t.payload)) AS j(k)
)
SELECT k AS field,
       COUNT(*) AS rows_present,
       SUM(CASE WHEN TRY_CAST(json_extract_string(t.payload, '$."' || k || '"') AS DOUBLE) = -1 THEN 1 ELSE 0 END) AS minus_one,
       SUM(CASE WHEN raw IS NULL OR json_type(raw) = 'NULL' THEN 1 ELSE 0 END) AS nulls,
       MIN(CASE WHEN TRY_CAST(json_extract_string(t.payload, '$."' || k || '"') AS DOUBLE) <> -1
                THEN TRY_CAST(json_extract_string(t.payload, '$."' || k || '"') AS DOUBLE) END) AS min,
       MAX(...) AS max
FROM kv JOIN "表" t ON true GROUP BY k ORDER BY k
```
