# 存储层（C1 子项目）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立本地数据仓库抽象层 —— `Store` 接口 + 可配置体系（路径/profile/后端/行为参数）+ DuckDB 惰性后端 + `qiyu store init` / `qiyu store status` 两条命令，使 D（同步引擎）可以开工、E（查询/沙箱）有稳定读入口。

**Architecture:** 新增 `src/store/` 一层：`types.ts`（接口，无 DuckDB 痕迹）、`config.ts`（配置文件读取 + 三级优先级 + fail-closed 校验）、`schema.ts`（声明式表定义 + 函数式迁移）、`retry.ts`（退避纯函数，时钟可注入）、`duckdb.ts`（唯一后端实现，`@duckdb/node-api` 经可注入 importer 惰性加载）、`index.ts`（后端注册表 + `openStore` 工厂）。命令层 `src/commands/store.ts` 只消费 `Store` 接口。`@duckdb/node-api` 进 `optionalDependencies`，`auth`/`api` 命令完全不加载它。

**Tech Stack:** Node ≥ 20.10、TypeScript ESM（相对 import 带 `.js` 后缀）、`@duckdb/node-api@1.5.6-r.1`（**唯一新增依赖，optionalDependency**）、vitest 2.1.9（`vitest run --maxWorkers=1 --no-file-parallelism`）。

**Spec:** `docs/superpowers/specs/2026-10-13-存储层-design.md`（**v3**，§十一 修订记录、§十 **65 条**验收判据）——**实施前必读**，本计划每个任务都在其验收编号下有对应落点。

## Review Focus

以下 5 类条件，spec 隐含要求但最容易被实现漏掉、且直接伤到使用者（Agent），按最可能出问题排序；每类在本计划里都有任务的测试钉住：

1. **魔数偏移写错导致 init 拒绝自家库**——DuckDB 的 `DUCK` 魔数在**偏移 8**（前 8 字节是块校验和），不在 0。spec §7.1 的裁决是**不自己校验魔数**、改依赖 DuckDB 自身报错。若实施者自作主张写「前 4 字节 == DUCK」，`store init` 重复跑会拒绝它自己刚建的库。测试见 Task 7（验收 41：init 后重复 init 仍退出码 0，且 schema_version 不变——验收 18）。
2. **`COUNT(*)` 返回字符串**——`getRowObjectsJson()` 把 BIGINT 映射为 `string`，`count(): Promise<number>` 若不显式 `Number()` 收敛就返回 `"1"`。测试见 Task 5（验收 21/31：`count(table) === 1` 严格数字相等）。
3. **退避把非锁错误也吞 30 秒**——若 `tryOpen` 的重试判据不是「message 含 `Conflicting lock`」，文件不存在/权限拒绝会被无谓退避。测试见 Task 4（验收 34：非锁错误立即抛）。
4. **`--pretty` 被静默吞掉**——B 项目为 `api`/`auth` 逐层钉过「`--pretty` 是合法 flag」；`store` 若按 spec 只写一句「未知参数 → help」，会复现 B 已修掉的静默吞。测试见 Task 7（验收 46：`store init --pretty` → 2、`store --help --pretty` → 0）。
5. **upsert 在事务内嵌套 BEGIN**——`upsert` 若无条件自开事务，`tx.upsert()` 会嵌套（DuckDB 不支持）。测试见 Task 5（验收 29a/29b：tx 内多批 upsert 回滚后全无；tx 外自开事务）。

```ts
// src/store/types.ts
// ⚠️ 本文件**不得**出现任何 DuckDB 类型（DuckDBInstance / getRowObjectsJson …）——
// C2 接外部后端时只新增 kysely.ts 与 BackendName 成员，不改本文件的方法签名。

export type BackendName = 'duckdb'
export type StoreMode = 'ro' | 'rw'

export interface StoreConfig {
  backend: BackendName
  path: string
  /** 读者拿锁的退避上限（毫秒）。**仅读者使用** —— 写者撞锁不重试（spec §5.2）。 */
  readOnlyRetryMs: number
  /** 多值 INSERT 每批行数。正整数；超限批次由实现二次切批。 */
  batchSize: number
  /** 后端专属配置（C2 的连接串等）。C1 忽略。 */
  options?: Record<string, unknown>
}

export interface QueryResult {
  columns: string[]
  /** JSON 安全值：无 BigInt、无 Date 包装对象。 */
  rows: Record<string, unknown>[]
}

/** 事务回调视图：**不含** query/init/close（spec §4.2.6 的防线分层）。 */
export type WriteTx = Omit<Store, 'query' | 'init' | 'close'>

export interface Store {
  /** 幂等建表 + 推进迁移。**仅 rw 模式合法**（ro 上调用 → usage 错误）。 */
  init(): Promise<void>
  /** 表名清单（含元数据表），**按名称排序**。 */
  tables(): Promise<string[]>
  /** 单表行数。返回 number —— BIGINT 聚合经 JSON 层是字符串，实现必须收敛。 */
  count(table: string): Promise<number>
  /**
   * 批量 upsert。**每行必须提供该表完整列集**，同一批次内键集必须一致（否则 usage）。
   * 事务语义：处于活动事务内则加入，否则自开单次事务（整批原子）。
   * 返回实际写入行数。
   */
  upsert(table: string, rows: Record<string, unknown>[]): Promise<number>
  /** 事务：回调内的写操作原子提交，抛异常整体回滚。不得嵌套（→ usage）。 */
  transaction<T>(fn: (tx: WriteTx) => Promise<T>): Promise<T>
  /**
   * 原始查询原语，位置参数用 `?` 占位。**不受白名单保护** —— 只接受可信代码的
   * 字面 SQL；E 的三层沙箱是对外唯一护栏。C1 不通过任何命令暴露它。
   */
  query(sql: string, params?: unknown[]): Promise<QueryResult>
  close(): Promise<void>
}

/** 工厂：按 cfg.backend 查后端注册表；未知后端 → usage 错误。 */
export function openStore(cfg: StoreConfig, mode: StoreMode): Promise<Store> {
  throw new Error('openStore 尚未实现（Task 6 落地）')
}
```

```ts
import { describe, it, expect, vi, beforeEach, afterEach } from 'vitest'
import { mkdtempSync, mkdirSync, writeFileSync, rmSync, chmodSync } from 'node:fs'
import { tmpdir } from 'node:os'
import { join } from 'node:path'
import { resolveStoreConfig } from '../../src/store/config.js'

let home = ''
const writeCfg = (obj: unknown): string => {
  const dir = join(home, '.config', 'qiyu')
  mkdirSync(dir, { recursive: true })
  const p = join(dir, 'config.json')
  writeFileSync(p, typeof obj === 'string' ? obj : JSON.stringify(obj))
  return p
}
beforeEach(() => { home = mkdtempSync(join(tmpdir(), 'qiyu-home-')) })
```

```ts
 * 解析 store 配置：命令行 > 环境变量 > 配置文件 > 内置默认（spec §3.2）。
 * ⚠️ 只读不写；配置文件由用户手工维护（`auth login` 归 G1，spec §3.5）。
 */
export function resolveStoreConfig(opts: ResolveOpts = {}): {
  config: StoreConfig; configPath: string; configExists: boolean
} {
  const home = opts.home ?? homedir()
  const configPath = opts.configPath ?? join(home, '.config', 'qiyu', 'config.json')
  const env = opts.env ?? {}
  const flags = opts.flags ?? {}

  let file: Record<string, unknown> = {}
  const configExists = existsSync(configPath)
  if (configExists) {
    let raw: string
    try {
      raw = readFileSync(configPath, 'utf8')
    } catch (e) {
      throw new Error(`无法读取配置文件 ${configPath}：${e instanceof Error ? e.message : String(e)}`)
    }
    try {
      file = JSON.parse(raw) as Record<string, unknown>
    } catch (e) {
      throw new Error(`配置文件 ${configPath} 不是合法 JSON：${e instanceof Error ? e.message : String(e)}`)
    }
    assertKnownKeys(file, KNOWN_TOP, '')
    // ⚠️ 权限检查（spec §3.4）：POSIX 下 group/other 有任何位 → 警告，不阻断。
    // C1 配置不含凭证；G1 加入凭证时此处须升级为拒绝（spec §3.4 的交接）。
    if (process.platform !== 'win32') {
      const mode = statSync(configPath).mode & 0o777
      if ((mode & 0o077) !== 0) {
        process.stderr.write(`配置文件 ${configPath} 权限过宽（建议 chmod 600）\n`)
      }
    }
  }

  const profiles = (file.profiles ?? {}) as Record<string, Record<string, unknown>>
  for (const [name, prof] of Object.entries(profiles)) {
    if (prof === null || typeof prof !== 'object' || Array.isArray(prof)) {
      throw new Error(`配置文件 profiles.${name} 必须是对象`)
    }
    assertKnownKeys(prof, KNOWN_PROFILE, `profiles.${name}.`)
    const store = (prof.store ?? {}) as Record<string, unknown>
    if (prof.store !== undefined && (store === null || typeof store !== 'object' || Array.isArray(store))) {
      // store 块存在但非对象 → fail-closed 显式报错（不静默走默认，spec §3.3）
      throw new Error(`配置文件 profiles.${name}.store 必须是对象`)
    }
    if (store !== null && typeof store === 'object' && !Array.isArray(store)) {
      assertKnownKeys(store, KNOWN_STORE, `profiles.${name}.store.`)
    }
  }

  const profileName = flags.profile ?? env.QIYU_PROFILE ?? (file.defaultProfile as string | undefined) ?? 'default'
  const prof = (profiles[profileName] ?? {}) as Record<string, unknown>
  const storeBlock = ((prof.store ?? {}) as Record<string, unknown>)

  const rawBackend = flags.backend ?? env.QIYU_STORE_BACKEND ?? (storeBlock.backend as string | undefined) ?? DEFAULTS.backend
  if (rawBackend !== 'duckdb') {
    throw new Error(`未知后端：${rawBackend}。C1 仅支持 duckdb（外部后端见 C2）`)
  }
  const rawPath = flags.db ?? env.QIYU_DB_PATH ?? (storeBlock.path as string | undefined) ?? DEFAULTS.relPath
  const readOnlyRetryMs = storeBlock.readOnlyRetryMs === undefined
    ? DEFAULTS.readOnlyRetryMs
    : assertPositiveInt(storeBlock.readOnlyRetryMs, `profiles.${profileName}.store.readOnlyRetryMs`)
  const batchSize = storeBlock.batchSize === undefined
    ? DEFAULTS.batchSize
    : assertPositiveInt(storeBlock.batchSize, `profiles.${profileName}.store.batchSize`)

  return {
    config: { backend: rawBackend as BackendName, path: expandHome(rawPath, home), readOnlyRetryMs, batchSize },
    configPath,
    configExists,
  }
}
```

```ts
// src/store/schema.ts
export interface ColumnDef {
  name: string
  type: 'VARCHAR' | 'INTEGER'
  nullable: boolean
  /** ⚠️ E 交付前无运行时读取者 —— 是给 E 的 `db describe` 的预置位（spec §6.2）。 */
  sensitive?: boolean
}
export interface TableDef { name: string; columns: ColumnDef[]; primaryKey: string[] }

const col = (name: string, type: 'VARCHAR' | 'INTEGER', nullable = true): ColumnDef =>
  ({ name, type, nullable, sensitive: false })

export const TABLES: TableDef[] = [
  { name: 'schema_version', columns: [col('version', 'INTEGER', false)], primaryKey: ['version'] },
  {
    name: 'sync_state',
    columns: [col('dataset', 'VARCHAR', false), col('watermark', 'VARCHAR'), col('range_status', 'VARCHAR'),
      col('last_error', 'VARCHAR'), col('locked_by', 'VARCHAR'), col('locked_at', 'VARCHAR')],
    primaryKey: ['dataset'],
  },
  {
    name: 'sync_gaps',
    columns: [col('dataset', 'VARCHAR', false), col('range_start', 'VARCHAR', false), col('range_end', 'VARCHAR'),
      col('reason', 'VARCHAR'), col('recorded_at', 'VARCHAR')],
    primaryKey: ['dataset', 'range_start'],
  },
  {
    name: 'tags',
    columns: [col('id', 'VARCHAR', false), col('name', 'VARCHAR', false), col('color', 'VARCHAR', false)],
    primaryKey: ['id'],
  },
]

export function tableByName(name: string): TableDef | undefined {
  return TABLES.find((t) => t.name === name)
}

/** ⚠️ 只产 v1 基线建表语句 —— 对已存在的库加不了列。任何 TABLES 变更必须新增迁移条目（spec §6.2）。 */
export function ddlFor(t: TableDef): string {
  const cols = t.columns.map((c) => `"${c.name}" ${c.type}${c.nullable ? '' : ' NOT NULL'}`).join(', ')
  const pk = t.primaryKey.map((k) => `"${k}"`).join(', ')
  return `CREATE TABLE IF NOT EXISTS "${t.name}" (${cols}, PRIMARY KEY (${pk}))`
}

/** 迁移条目：函数式（可 ALTER TABLE）。一版本一行；当前版 = MAX(version)（spec §6.2）。 */
export interface Migration { version: number; up: (exec: (sql: string) => Promise<void>) => Promise<void> }

export const MIGRATIONS: Migration[] = [
  {
    version: 1,
    up: async (exec) => {
      for (const t of TABLES) await exec(ddlFor(t))
    },
  },
]

export const LATEST_VERSION = MIGRATIONS.reduce((m, x) => Math.max(m, x.version), 0)
```

```ts
// src/store/retry.ts
// ⚠️ 曲线是**固定间隔**（实测 2.6s/13 次成功 ≈ 200ms 间隔，spec §5.2）——
// 不是指数：指数曲线在剩余预算不足时会大幅越过 maxMs。

/** 锁冲突的识别规则（spec §5.2 定死）：message 含 `Conflicting lock`。 */
export function isLockError(e: unknown): boolean {
  const msg = e instanceof Error ? e.message : String(e)
  return msg.includes('Conflicting lock')
}

export interface RetryOpts<T> {
  tryOpen: () => Promise<T>
  isRetryable: (e: unknown) => boolean
  maxMs: number
  intervalMs?: number
  sleep?: (ms: number) => Promise<void>
  now?: () => number
}

const defaultSleep = (ms: number): Promise<void> => new Promise((r) => setTimeout(r, ms))

/** 有界重试：可重试错误按固定间隔重试至 maxMs，超限抛最后一个错误。 */
export async function retryWithBackoff<T>(opts: RetryOpts<T>): Promise<T> {
  const intervalMs = opts.intervalMs ?? 200
  const sleep = opts.sleep ?? defaultSleep
  const now = opts.now ?? (() => Date.now())
  const start = now()
  for (;;) {
    try {
      return await opts.tryOpen()
    } catch (e) {
      if (!opts.isRetryable(e)) throw e
      if (now() - start + intervalMs > opts.maxMs) throw e
      await sleep(intervalMs)
    }
  }
}
```

```ts
// src/store/duckdb.ts
import { MIGRATIONS, LATEST_VERSION, tableByName, type TableDef } from './schema.js'
import { retryWithBackoff, isLockError } from './retry.js'
import type { QueryResult, Store, StoreConfig, StoreMode, WriteTx } from './types.js'

/** 可注入的导入边界 —— 单测 mock 它模拟依赖缺失（spec §5.1）。 */
export type DuckDbImporter = () => Promise<unknown>
const defaultImporter: DuckDbImporter = () => import('@duckdb/node-api')

export interface DuckDbDeps {
  importer?: DuckDbImporter
  sleep?: (ms: number) => Promise<void>
  now?: () => number
}

/** 识别 ERR_MODULE_NOT_FOUND 并取出缺失的 specifier（spec §5.1 的二分规则）。 */
export function isModuleNotFound(e: unknown): { missing: string } | null {
  const err = e as { code?: string; message?: string }
  if (err?.code !== 'ERR_MODULE_NOT_FOUND') return null
  const m = /Cannot find (?:package|module) '([^']+)'/.exec(err.message ?? '')
  return { missing: m?.[1] ?? '' }
}

/** 依赖缺失 → store_not_initialized（按缺失 specifier 前缀二分 hint，spec §5.1）。 */
function depError(e: unknown): Error {
  const mn = isModuleNotFound(e)
  const err = new Error(`无法加载 DuckDB 依赖：${e instanceof Error ? e.message : String(e)}`)
  ;(err as { kind?: string }).kind = 'store_not_initialized'
  ;(err as { hint?: string }).hint = mn && mn.missing.startsWith('@duckdb/node-bindings')
    ? '当前平台无 DuckDB 预编译包（无 node-gyp 回退）。请改用外部后端（C2）或受支持的平台'
    : '未安装 DuckDB 依赖。请运行：npm i @duckdb/node-api@1.5.6-r.1'
  return err
}

/** usage 错误（退出码 2）：带 kind 供命令层经 mapThrownToExit 归 usage。 */
function usage(msg: string): Error {
  const e = new Error(msg)
  ;(e as { kind?: string }).kind = 'usage'
  return e
}

export async function createDuckDbStore(cfg: StoreConfig, mode: StoreMode, deps: DuckDbDeps = {}): Promise<Store> {
  let mod: { DuckDBInstance: { create: (p: string, o?: unknown) => Promise<unknown> } }
  try {
    mod = (await (deps.importer ?? defaultImporter)()) as typeof mod
  } catch (e) {
    throw depError(e)
  }

  const open = async (): Promise<{ conn: unknown; inst: unknown }> => {
    // ⚠️ 只读模式必须真的以 READ_ONLY 打开 —— 这是 ro→ro 并发可用的前提（spec §5.2）。
    // DuckDB Node API 的配置项名以安装后的 .d.ts 为准（预计为 create(path, { access_mode: 'READ_ONLY' })）；
    // 若签名不同，按真实签名调整本行，但**不得**在 ro 模式下以可写方式打开。
    const inst = mode === 'ro'
      ? await mod.DuckDBInstance.create(cfg.path, { access_mode: 'READ_ONLY' })
      : await mod.DuckDBInstance.create(cfg.path)
    const conn = await (inst as { connect: () => Promise<unknown> }).connect()
    return { conn, inst }
  }

  let conn: unknown
  let inst: unknown
  if (mode === 'ro') {
    // 读者：锁冲突时退避重试（spec §5.2）；**超限后必须包装 store_locked**（v3.1 修——
    // v1 计划直接重抛原始错误，经 thrownToExit 会变成退出码 2 的 usage，违反验收 35）。
    try {
      const r = await retryWithBackoff({
        tryOpen: open, isRetryable: isLockError, maxMs: cfg.readOnlyRetryMs,
        sleep: deps.sleep, now: deps.now,
      })
      conn = r.conn; inst = r.inst
    } catch (e) {
      if (isLockError(e)) {
        const err = new Error(`数据库被写进程占用（等待 ${cfg.readOnlyRetryMs}ms 后超时）：${cfg.path}`)
        ;(err as { kind?: string }).kind = 'store_locked'
        ;(err as { retryable?: boolean }).retryable = true
        ;(err as { hint?: string }).hint = '数据库被写进程占用，请稍后重试'
        throw err
      }
      throw e
    }
  } else {
    // 写者不重试（spec §5.2）：撞锁立即抛。
    try {
      const r = await open()
      conn = r.conn; inst = r.inst
    } catch (e) {
      if (isLockError(e)) {
        const err = new Error(`数据库被写进程占用：${cfg.path}`)
        ;(err as { kind?: string }).kind = 'store_locked'
        ;(err as { retryable?: boolean }).retryable = true
        ;(err as { hint?: string }).hint = '另一个进程持有数据库写锁。若在同步中请等其完成，否则稍后重试'
        throw err
      }
      throw e
    }
  }

  const c = conn as { run: (sql: string, params?: unknown[]) => Promise<unknown> }
  let closed = false
  let inTx = false

  // ⚠️ 所有语句执行收敛到这一个方法 —— 测试 spy 的落点（spec §5.3）。
  // ⚠️ **挂载与调用契约（v3.1 定死，消除二选一）**：
  // ① store 的所有方法体**必须经 `store.execSql(...)` 调用**（属性查找发生在调用时，
  //    vi.spyOn 替换后即命中 spy）——闭包直调 execSql 会绕过 spy，「1000 行批量 1 条语句」
  //    断言形同虚设（v1 计划实测缺陷，D/E/F 三组独立发现）；
  // ② `Object.defineProperty` 必须 `writable: true, configurable: true` —— 默认
  //    configurable:false 会让 vi.spyOn 重定义属性时直接抛 TypeError；
  // ③ 挂为**不可枚举**（不污染 JSON 输出与接口形状）。
  const execSql = async (sql: string, params: unknown[] = []): Promise<unknown> => {
    if (closed) throw usage('数据库连接已关闭')
    return c.run(sql, params)
  }

  const assertTable = (name: string): TableDef => {
    const t = tableByName(name)
    if (!t) throw usage(`未知表：${name}`)
    return t
  }

  const assertRows = (t: TableDef, rows: Record<string, unknown>[]): void => {
    if (rows.length === 0) return
    const cols = t.columns.map((x) => x.name)
    for (let i = 0; i < rows.length; i++) {
      const keys = Object.keys(rows[i])
      for (const k of keys) if (!cols.includes(k)) throw usage(`未知列：${k}（表 ${t.name}）`)
      for (const cd of t.columns) {
        if (!(cd.name in rows[i])) throw usage(`表 ${t.name} 缺少列：${cd.name}`)
        if (rows[i][cd.name] === null && !cd.nullable) throw usage(`列 ${cd.name} 不允许 null（表 ${t.name}）`)
      }
    }
  }

  const doUpsert = async (t: TableDef, rows: Record<string, unknown>[]): Promise<number> => {
    if (rows.length === 0) return 0
    const cols = t.columns.map((x) => x.name)
    const quoted = cols.map((x) => `"${x}"`).join(', ')
    const nonKey = cols.filter((x) => !t.primaryKey.includes(x))
    const setClause = nonKey.map((x) => `"${x}" = excluded."${x}"`).join(', ')
    const pk = t.primaryKey.map((x) => `"${x}"`).join(', ')
    let written = 0
    // ⚠️ 二次切批：batchSize 行 × 列数可能超 DuckDB 绑定参数上限（实测 ≈65535，
    // spec §5.4）——按 floor(65000 / 列数) 行二次切批，保证单语句参数数不超限。
    const maxRowsPerStmt = Math.max(1, Math.floor(65000 / cols.length))
    for (let i = 0; i < rows.length; i += Math.min(cfg.batchSize, maxRowsPerStmt)) {
      const batch = rows.slice(i, i + Math.min(cfg.batchSize, maxRowsPerStmt))
      const placeholders = batch.map(() => `(${cols.map(() => '?').join(', ')})`).join(', ')
      const params = batch.flatMap((r) => cols.map((k) => r[k] ?? null))
      await store.execSql(
        `INSERT INTO "${t.name}" (${quoted}) VALUES ${placeholders} ON CONFLICT (${pk}) DO UPDATE SET ${setClause}`,
        params)
      written += batch.length
    }
    return written
  }

  // ⚠️ store 自引用：方法体经 store.execSql 调用（见下方契约）。`as unknown as Store`
  // 断言容忍初始字面量尚未含 execSql 键（返回前 defineProperty 挂上）；方法参数显式
  // 标注（自引用打断上下文推导，不标会隐式 any）。
  const store = {
    async init() {
      if (mode === 'ro') throw usage('只读模式下不能初始化（需 rw 模式）')
      // 他人库防线（spec §6.1）：已有表但无 schema_version → 拒绝。
      const existing = await store.execSql(`SELECT table_name FROM information_schema.tables WHERE table_schema = 'main'`)
      const names = ((existing as { getRowObjectsJson?: () => Record<string, unknown>[] }).getRowObjectsJson?.() ?? [])
        .map((r) => String(r.table_name))
      if (names.length > 0 && !names.includes('schema_version')) {
        // ⚠️ 他人库 → store_not_initialized、退出码 1（spec §8.2 成因 6）——不是 usage。
        const err = new Error(`目标库不是本 CLI 创建的（含表 ${names.join(', ')}）：${cfg.path}`)
        ;(err as { kind?: string }).kind = 'store_not_initialized'
        ;(err as { hint?: string }).hint = '目标库不是本 CLI 创建的，请换 --db 路径'
        throw err
      }
      const cur = names.includes('schema_version')
        ? await store.execSql('SELECT COALESCE(MAX(version), 0) AS v FROM schema_version')
        : null
      const v = cur === null ? 0 : Number(((cur as { getRowObjectsJson?: () => Record<string, unknown>[] }).getRowObjectsJson?.() ?? [{ v: 0 }])[0].v)
      for (const m of MIGRATIONS.filter((x) => x.version > v).sort((a, b) => a.version - b.version)) {
        await store.execSql('BEGIN')
        try {
          await m.up((sql) => store.execSql(sql).then(() => undefined))
          await store.execSql('INSERT INTO schema_version (version) VALUES (?)', [m.version])
          await store.execSql('COMMIT')
        } catch (e) {
          // 迁移失败：回滚且**不推进**版本 —— 下次 init 重放该迁移（验收 19/20）。
          await store.execSql('ROLLBACK')
          throw e
        }
      }
    },
    async tables(): Promise<string[]> {
      const r = await store.execSql(`SELECT table_name FROM information_schema.tables WHERE table_schema = 'main'`)
      return ((r as { getRowObjectsJson?: () => Record<string, unknown>[] }).getRowObjectsJson?.() ?? [])
        .map((x) => String(x.table_name)).sort()
    },
    async count(table: string): Promise<number> {
      assertTable(table)
      const r = await store.execSql(`SELECT COUNT(*) AS n FROM "${table}"`)
      const v = ((r as { getRowObjectsJson?: () => Record<string, unknown>[] }).getRowObjectsJson?.() ?? [{ n: 0 }])[0].n
      return Number(v)   // ⚠️ BIGINT → string，必须收敛（spec §5.4）
    },
    async upsert(table: string, rows: Record<string, unknown>[]): Promise<number> {
      const t = assertTable(table)
      assertRows(t, rows)
      if (inTx) return doUpsert(t, rows)
      await store.execSql('BEGIN')
      try {
        const n = await doUpsert(t, rows)
        await store.execSql('COMMIT')
        return n
      } catch (e) {
        await store.execSql('ROLLBACK')
        throw e
      }
    },
    async transaction<T>(fn: (tx: WriteTx) => Promise<T>): Promise<T> {
      if (inTx) throw usage('不得嵌套事务')
      await store.execSql('BEGIN')
      inTx = true
      try {
        // ⚠️ 真实投影而非 cast：WriteTx 类型上不含 query/init/close（spec §4.2.6 防线分层），
        // 运行时对象也不得携带 —— 直接传 store 的话 `Object.keys(tx)` 可枚举出 query。
        const tx: WriteTx = {
          tables: () => store.tables(),
          count: (t: string) => store.count(t),
          upsert: (t: string, rows: Record<string, unknown>[]) => store.upsert(t, rows),
          transaction: <U>(f: (tx2: WriteTx) => Promise<U>) => store.transaction(f),
        }
        const r = await fn(tx)
        await store.execSql('COMMIT')
        return r
      } catch (e) {
        await store.execSql('ROLLBACK')
        throw e
      } finally {
        inTx = false
      }
    },
    async query(sql: string, params?: unknown[]): Promise<QueryResult> {
      const r = await store.execSql(sql, params ?? [])
      const rows = (r as { getRowObjectsJson?: () => Record<string, unknown>[] }).getRowObjectsJson?.() ?? []
      // 空结果集也要给真实列名（不能留空数组）——DuckDB 结果对象带列元数据；
      // 若按 rows[0] 推列名，空集会丢列（实测陷阱，v3.1 修）。
      const cols = rows.length > 0
        ? Object.keys(rows[0])
        : ((r as { getColumnNames?: () => string[] }).getColumnNames?.() ?? [])
      return { columns: cols, rows } as QueryResult
    },
    async close(): Promise<void> {
      if (closed) return
      closed = true
      await (inst as { close?: () => Promise<void> })?.close?.()
    },
  } as unknown as Store
  // ⚠️ 挂载契约见上方 execSql 注释：不可枚举 + writable + configurable（缺 configurable
  // 会让 vi.spyOn 重定义时抛 TypeError）；方法体一律 store.execSql(...)（属性调用时查找）。
  Object.defineProperty(store, 'execSql', { value: execSql, enumerable: false, writable: true, configurable: true })
  return store
}
```

```ts
// src/store/index.ts
import { createDuckDbStore } from './duckdb.js'
import type { BackendName, Store, StoreConfig, StoreMode } from './types.js'

/**
 * 后端注册表（spec §4.2.4）—— 惰性映射，使 openStore 不必静态 import duckdb.js，
 * 这是 optionalDependency 惰性加载的落点。C2 在此加 'postgres'|'mysql'|'sqlite'。
 */
export const BACKENDS: Record<BackendName, (cfg: StoreConfig, mode: StoreMode) => Promise<Store>> = {
  duckdb: (cfg, mode) => createDuckDbStore(cfg, mode),
}

export async function openStore(cfg: StoreConfig, mode: StoreMode): Promise<Store> {
  const make = BACKENDS[cfg.backend]
  if (!make) {
    const e = new Error(`未知后端：${cfg.backend}。C1 仅支持 duckdb（外部后端见 C2）`)
    ;(e as { kind?: string }).kind = 'usage'
    throw e
  }
  return make(cfg, mode)
}
```

```ts
const USAGE = `用法：qiyu store <子命令> [参数]

子命令：
  store init [--db <path>] [--profile <name>] [--backend <name>]
                           初始化本地数据仓库（DuckDB）
  store status [--db <path>] [--profile <name>] [--backend <name>]
                           查看数据仓库状态与各表行数

⚠️ 存储配置需手工编辑 ~/.config/qiyu/config.json（CLI 不会自动创建）。
   也可用 --db / QIYU_DB_PATH 直接指定库路径。
`

const KNOWN = new Set(['--help', '-h', '--pretty'])

function parseFlags(argv: string[]): { db?: string; profile?: string; backend?: string; rest: string[] } {
  const out: { db?: string; profile?: string; backend?: string; rest: string[] } = { rest: [] }
  for (let i = 0; i < argv.length; i++) {
    const a = argv[i]
    if (a === '--db' || a === '--profile' || a === '--backend') {
      const v = argv[i + 1]
      // 值位守卫（B 的 isBodyValue 同族惯例）：值位缺失或以 -- 开头 → 报缺值，
      // 否则 `store init --db --profile x` 会把 --profile 当路径（v1 计划缺陷）。
      if (v === undefined || v.startsWith('--')) throw new Error(`${a} 缺少取值`)
      if (a === '--db') out.db = v
      else if (a === '--profile') out.profile = v
      else out.backend = v
      i++
    } else out.rest.push(a)
  }
  return out
}

function thrownToExit(e: unknown): number {
  const err = e as { kind?: string; message?: string; hint?: string; retryable?: boolean }
  if (err.kind && err.kind !== 'usage') {
    return fail({ code: err.kind, kind: err.kind, retryable: err.retryable ?? false,
      message: err.message ?? String(e), hint: err.hint })
  }
  // ⚠️ 无 kind 的错误分两类（spec §8.2 验收 41/54）：
  // ① DuckDB 拒绝打开非 DuckDB 文件 / 执行期错误 → 环境/数据问题，退出码 1、internal；
  // ② 其余 → 用法错误，退出码 2（usageFail 双通道）。
  const msg = err.message ?? String(e)
  if (/not a valid DuckDB database/i.test(msg)) {
    return fail({ code: 'store_not_initialized', kind: 'store_not_initialized', retryable: false,
      message: `无法打开 ${msg}`, hint: '该路径已存在且不是 DuckDB 数据库，请换 --db 路径' })
  }
  return fail({ code: 'internal', kind: 'internal', retryable: false,
    message: msg, hint: '写入被数据库约束拒绝或执行期错误' })
}

export async function storeCommand(argv: string[]): Promise<number> {
  const [sub, ...rest] = argv
  if (sub === undefined || sub === '--help' || sub === '-h') {
    // --help 不吞额外参数；--pretty 豁免（B 惯例）
    const extra = rest.filter((a) => !KNOWN.has(a))
    if (extra.length > 0) return usageFail(`未知参数：${extra.join(' ')}。--help 不接受额外参数`)
    process.stdout.write(USAGE)
    return 0
  }
  if (sub !== 'init' && sub !== 'status') {
    // store 级：--pretty 是合法 flag（承诺过未实现），不是「未知子命令」（B 惯例，cli.ts:54 同族）
    if (sub === '--pretty') return usageFail('--pretty 尚未实现 —— 目前只输出紧凑 JSON')
    return usageFail(`未知子命令：${sub}\n可用子命令：init、status`)
  }
  // 子命令级：**先 parseFlags**（消费带值 flag 的值位置），再判未知参数（spec §7.3/验收 46）。
  // ⚠️ 次序不能反：若先过滤「未知 token」再 parseFlags，`store init --db <path>` 的
  // --db 及其值会被当未知参数误拒（v1 计划的实测缺陷，D/F 组独立发现）。
  if (rest.includes('--help') || rest.includes('-h')) {
    const rawRest = rest.filter((a) => !KNOWN.has(a))
    if (rawRest.length > 0) return usageFail(`未知参数：${rawRest.join(' ')}`)
    process.stdout.write(USAGE)
    return 0
  }
  if (rest.includes('--pretty')) return usageFail('--pretty 尚未实现 —— 目前只输出紧凑 JSON')

  let flags
  try { flags = parseFlags(rest) } catch (e) { return usageFail((e as Error).message) }
  // parseFlags 之后剩下的 rest 才是真正的未知参数（带值 flag 的值位已被消费）
  if (flags.rest.length > 0) return usageFail(`未知参数：${flags.rest.join(' ')}`)

  let resolved
  try {
    resolved = resolveStoreConfig({ flags: { db: flags.db, profile: flags.profile, backend: flags.backend },
      env: { QIYU_DB_PATH: process.env.QIYU_DB_PATH, QIYU_STORE_BACKEND: process.env.QIYU_STORE_BACKEND, QIYU_PROFILE: process.env.QIYU_PROFILE } })
  } catch (e) { return usageFail((e as Error).message) }

  const { config, configPath, configExists } = resolved

  if (sub === 'init') {
    // 文件前置检查（spec §7.1 步骤 2；验收 41）
    try {
      // 符号链接 → 拒绝（lstat 不跟随；spec §7.1 步骤 2，防误操作非防对抗）
      let st: ReturnType<typeof statSync>
      try { st = lstatSync(config.path) } catch { st = undefined as never }
      if (st !== undefined && st.isFile() === false && st.isDirectory() === true) {
        return fail({ code: 'store_not_initialized', kind: 'store_not_initialized', retryable: false,
          message: `不是普通文件：${config.path}`, hint: '请用 --db 指定数据库文件路径' })
      }
      if (st !== undefined && st.isFile() === false && st.isSymbolicLink() === false && st.isDirectory() === false) {
        // 其它特殊文件（设备/套接字等）同样拒绝
        return fail({ code: 'store_not_initialized', kind: 'store_not_initialized', retryable: false,
          message: `不是普通文件：${config.path}`, hint: '请用 --db 指定数据库文件路径' })
      }
      if (st !== undefined && st.isSymbolicLink() === true) {
        return fail({ code: 'store_not_initialized', kind: 'store_not_initialized', retryable: false,
          message: `目标是符号链接：${config.path}`, hint: '--db 目标是符号链接，请给出真实路径' })
      }
      // 父目录不存在 → mkdirSync(recursive)；失败 → 退出码 1、message 含路径与底层原因
      const parent = dirname(config.path)
      try { mkdirSync(parent, { recursive: true }) } catch (e) {
        return fail({ code: 'store_not_initialized', kind: 'store_not_initialized', retryable: false,
          message: `无法创建父目录 ${parent}：${e instanceof Error ? e.message : String(e)}`,
          hint: '请检查父目录权限，或用 --db 换一个可写的路径' })
      }
      // ⚠️ 魔数在偏移 8（前 8 字节是块校验和）——不自写魔数检查，交给 DuckDB 打开时校验：
      // 非 DuckDB 文件打开即抛 "not a valid DuckDB database"，由 thrownToExit 映射。
    } catch { /* lstat 失败按不存在处理 → DuckDB 会创建 */ }
    let store
    try {
      store = await openStore(config, 'rw')
    } catch (e) { return thrownToExit(e) }
    try {
      await store.init()
      const tables = await store.tables()
      const sv = await store.query('SELECT COALESCE(MAX(version),0) AS v FROM schema_version')
      return ok({ path: config.path, backend: config.backend, config_path: configPath,
        config_exists: configExists,
        schema_version: Number(sv.rows[0]?.v ?? 0),
        tables })
    } catch (e) { return thrownToExit(e) } finally { await store.close() }
  }

  // status
  try { statSync(config.path) } catch {
    return fail({ code: 'store_not_initialized', kind: 'store_not_initialized', retryable: false,
      message: `数据库文件不存在：${config.path}`, hint: '数据库尚未初始化。请先运行：qiyu store init' })
  }
  if (!statSync(config.path).isFile()) {
    return fail({ code: 'store_not_initialized', kind: 'store_not_initialized', retryable: false,
      message: `不是普通文件：${config.path}`, hint: '数据库尚未初始化。请先运行：qiyu store init' })
  }
  let store
  try { store = await openStore(config, 'ro') } catch (e) { return thrownToExit(e) }
  try {
    const names = await store.tables()
    if (!names.includes('schema_version')) {
      return fail({ code: 'store_not_initialized', kind: 'store_not_initialized', retryable: false,
        message: `数据库结构不完整（缺表）：${config.path}`,
        hint: names.length > 0 ? '目标库不是本 CLI 创建的，请换 --db 路径' : '数据库结构不完整（缺表）。请运行：qiyu store init' })
    }
    const tables: Array<{ name: string; rows: number }> = []
    for (const n of names) tables.push({ name: n, rows: await store.count(n) })
    const sv = await store.query('SELECT COALESCE(MAX(version),0) AS v FROM schema_version')
    return ok({ path: config.path, backend: config.backend, config_path: configPath,
      config_exists: configExists,
      schema_version: Number(sv.rows[0]?.v ?? 0), tables })
  } catch (e) { return thrownToExit(e) } finally { await store.close() }
}
```
